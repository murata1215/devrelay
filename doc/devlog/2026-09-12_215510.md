# classic: スレッド一覧（左ペイン）の幅を可変にする（web のみ）

## Context

前サイクル（`f06f212` + `5a5762a`、2026-09-12）で Servers / Agents を右レールへ移した結果、classic の左ペインは
スレッド一覧（`ThreadList`）だけになった。しかしその幅は `ThreadList.tsx` の `w-56`（= 224px）固定のままで、
サイクル名のような長いタイトルは `truncate` で途中から見えない。右レール（`RightRail.tsx`）はドラッグでの幅変更と
localStorage 永続化を既に持っているので、同じ仕組みを左ペインにも付けた。

制約の核心は「`ThreadList.tsx` は `/lite` と共有しているので触れない」こと。よって幅の state・localStorage・
ドラッグハンドルはすべて classic 側の新規ラッパー（`ThreadPane.tsx`）に置き、`ThreadList` 自身の `w-56` は
`index.css` の**アンレイヤー CSS**（Tailwind の `@layer utilities` に必ず勝つ）で上書きした。
リサイズ処理は右レールからコピペせず、新規フック `usePanelResize` + 純ロジック `panel-resize-rules.ts` に
一本化し、`RightRail.tsx` もそれに載せ替えた。

スコープは `apps/web` のみ。server / agents / packages / prisma / Lite / `ThreadList.tsx` は無変更。
`apps/server` 無変更 → `pm2 restart` 不要・Agent `u` 不要（web の再ビルド + ハードリロードのみ）。

## 実装

### 1. `apps/web/src/lib/panel-resize-rules.ts`（新規・純ロジック・外部 import ゼロ）

- `clampWidth(width, min, max)` — `Math.min(max, Math.max(min, width))`
- `readWidth(raw, { min, max, fallback })` — 旧 `right-rail-rules.ts` の幅読み取り関数の契約をそのまま移植
  （`null` → fallback（clamp しない）／`!Number.isFinite` → fallback／それ以外 → `clampWidth`）
- `computeResizeWidth({ startWidth, startX, clientX, edge, min, max })` —
  `edge:'left'`（右レール）→ `startX - clientX`、`edge:'right'`（スレッド一覧）→ `clientX - startX`
- 定数: `THREAD_PANE_WIDTH_STORAGE_KEY='devrelay-thread-list-width'` / `_DEFAULT=224` / `_MIN=200` / `_MAX=480`
- クラス文字列ヘルパー: `resolveThreadPaneShellClass()`、`resolveResizeHandleClass(edge)`、`RESIZE_OVERLAY_CLASS`

### 2. `apps/web/tsconfig.test.json`

`include` に `"src/lib/panel-resize-rules.ts"` を素の文字列で追記（`lite-source-guards.test.mjs` が `JSON.parse`
するためコメント不可）。

### 3. `apps/web/tests/panel-resize-rules.test.mjs`（新規・48 ケース）

ユニット（`clampWidth`/`readWidth`/`computeResizeWidth`、旧 `clampRailWidth` との等価性証明含む）+ 定数 +
クラス文字列 + 静的ガード（Lite 無変更・ThreadList 契約維持・二重実装なし・算術がテスト可能な場所にある・
CSS ガード・ChatPage 配線・モバイル無効化・tsconfig.test.json include・CJK 外部なし）。

### 4. `apps/web/src/hooks/usePanelResize.ts`（新規・唯一のドラッグ実装）

`RightRail.tsx` の `safeGetItem`/`safeSetItem` と `handleResizeStart` を移設・一般化。算術は必ず
`computeResizeWidth(...)` を呼び、フック内に `Math.min`/`Math.max` を書かない。

既存実装からの意図的な差分（どちらも現行の潜在バグ修正）:
- `widthRef.current` を mousemove ハンドラ内で即時更新してから `setWidth` する（旧実装は render 中に ref を
  同期していたため、最後の mousemove が React にコミットされる前に mouseup が来ると 1 イベント分古い幅が
  保存され得た）
- アンマウント時にドラッグ中のリスナーを確実に解除する（`useEffect` クリーンアップ。旧実装は mouseup でのみ
  解除しておりドラッグ中に呼び出し元がアンマウントされるとリスナーが漏れ続けていた）

### 5. `apps/web/src/components/RightRail.tsx`

自前のドラッグ実装（`useState`/`useRef`/`useCallback`、`readRailWidth`/`clampRailWidth`、mousemove/mouseup
リスナー）を削除し `usePanelResize({ storageKey: RAIL_WIDTH_STORAGE_KEY, min: RAIL_WIDTH_MIN, max: RAIL_WIDTH_MAX,
defaultWidth: RAIL_WIDTH_DEFAULT, edge: 'left' })` に載せ替え。挙動は不変（`style={{ width }}` / `hidden md:flex`
/ `hidden lg:flex` / オーバーレイ・ハンドルの JSX 位置は現行のまま）。`RAIL_WIDTH_STORAGE_KEY` 識別子は既存テスト
ガードのため `RightRail.tsx` 内に残した。

### 6. `apps/web/src/lib/right-rail-rules.ts`

`clampRailWidth`/`readRailWidth` を削除し `panel-resize-rules.ts` の汎用関数に委譲する旨のコメントに置換
（`^import` ゼロ規約のため委譲コードは書けず、`RightRail.tsx` 側が `RAIL_WIDTH_*` 定数を渡す形にした）。
`RAIL_*` 定数とその他の export は全て維持。

### 7. `apps/web/tests/right-rail-rules.test.mjs`

`clampRailWidth`/`readRailWidth` の import・describe を `panel-resize-rules.js` の `clampWidth`/`readWidth` に
`RAIL_WIDTH_MIN`/`MAX`/`DEFAULT` を渡す形へ差し替え。アサーション値は変更なし。**載せ替え前後で
`node --test tests/right-rail-rules.test.mjs` の pass 件数が 39→39 で変化していないことを確認済み**
（export 削除によるリンクエラーでファイルごと落ちていないことの実測）。

### 8. `apps/web/src/index.css`

```css
.thread-pane { width: 14rem; }
@media (min-width: 48rem) {
  .thread-pane { width: var(--thread-pane-w, 14rem); }
  .thread-pane > :not(.panel-resize-handle) { width: 100%; }
}
```

`> div` ではなく `:not(.panel-resize-handle)` にすることでハンドル自身が幅 100% に膨らみクリックが全てドラッグ
扱いになる事故を防止。`768px` ではなく `48rem`（Tailwind v4 の `md` と一致）。ビルド後 CSS に
`--thread-pane-w`/`:not(.panel-resize-handle)` が残っていることを確認済み。

### 9. `apps/web/src/components/ThreadPane.tsx`（新規）

`usePanelResize` を呼び、`collapsed` のときはラッパーを一切描かず `<>{children}</>` を返す（フックは早期 return
より前で呼ぶ）。展開時は `relative flex min-h-0 shrink-0 thread-pane` のラッパーに `--thread-pane-w` を注入し、
子とリサイズハンドル（`<span className="panel-resize-handle ...">`）を描画。ラッパーが `flex` であることは
`ThreadList.tsx` の `z-[35]` stacking context を維持するために必須。

### 10. `apps/web/src/pages/ChatPage.tsx`

`import { ThreadPane } from '../components/ThreadPane';` を1行追加し、既存 `<ThreadList ... />` を
`<ThreadPane collapsed={threadPanelCollapsed}>...</ThreadPane>` で囲んだのみ（props 変更なし・インデントのみ）。
