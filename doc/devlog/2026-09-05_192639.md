# サイクル: #363 Devin プランモード「ツールが許可されず返事が返ってこない」の根治

## 要求

ユーザー報告（`DESKTOP-5U400FO/lfuser` / `Lafit` / Devin CLI / プランモード）: 質問
「MB01の概要を教えて」に対し Devin が前置き1文だけ返して無言終了する。`localCommit=3068778`
（#362 反映済み）でも直っていないとの申告を受け、プランモードで根本原因を再調査した。

## 実行（設計と実装）

Devin 公式ドキュメント（`docs.devin.ai/cli/reference/permissions`）と `devin --help`
（3000.6.7）の逐語確認により、#362 が前提としていた2点がいずれも誤りだったと判明:

1. `Exec()` は glob ではなく「プレフィックス一致」であり `Exec(**)` は明示的に無効なルール
   （"Exec(\*\*) is not valid"）。#260 以来の `deny: ["Write(**)","Exec(**)"]` の
   `Exec(**)` は**元々一度も機能していなかった**——#362 の「deny から `Exec(**)` を外す」は
   実質何も変えていなかった。
2. `--permission-mode auto` は「読み取り専用ツールのみ」を自動承認するだけで、シェル実行
   （Exec）は対象外（`devin --help` 実測: `"auto" auto-approves read-only tools, ...`）。
   「安全と判断したツールを自動承認」という #362 までの理解自体が `smart` の説明の取り違え
   だった。

この二重の誤解により、DevRelay 自身の調査系スキル（`devrelay-list-inventory` 等、実体は
すべて bash スクリプト）は allow にも deny にも一致するルールが一つも無いまま
「承認待ち→非対話 `-p` モードでは無言終了」を #260 から #362 まで踏み続けていたと結論。

**実装**:
1. 新規純関数モジュール `agents/{linux,macos,windows}/src/services/devin-plan-config.ts`
   （3 OS byte-for-byte 同一、外部 import ゼロ）に `buildDevinPlanConfig()`/
   `resolveDevinPlanPermissionMode()` を実装。Exec 許可プレフィックス（読み取り専用コマンド +
   `git log`/`git status`/`git diff`/`git show`/`git branch` + DevRelay スキルディレクトリ
   配下の bash 実行、クォート有無・POSIX/Windows パス区切り4パターン）と Exec 拒否プレフィックス
   （書き込みコマンド + `sudo`）を明示生成し、`strictExec` キルスイッチ時は `Exec(**)` を
   一切出力しない。`--permission-mode` は対応していれば `smart`（ルール不一致時のみ安全性を
   自動判定）を優先し、非対応時は `auto` にフォールバック。
2. `agents/{linux,macos,windows}/src/services/ai-runner.ts` のプランモード分岐を上記2関数
   経由に置き換え、`probeDevinCapabilities()` に `permissionModeSmart` を追加
   （モジュールレベルのキャッシュ変数の型注釈にも追従、#347 の既知の罠を回避）。
3. `packages/shared/src/i18n.ts` の `devin.readonlyUnsupported` の案内例から無効な
   `Exec(**)` を削除しプレフィックス形式に訂正（キー名・`{detail}` は不変）。
4. `agents/{linux,macos}/tests/devin-plan-config.test.mjs`（byte-for-byte 同一、17件）を新設。
5. `README.md`・`rules/project.md`・`doc/changelog.md` を「`Exec()` はプレフィックス一致・
   `Exec(**)` は無効・`auto` は read-only のみ・`smart` が安全判定」に訂正、本ファイルと
   `doc/devlog/INDEX.md` を追加。

## 発見

`Exec(**)` が無効ルールだったこと自体は #362 サイクルの前提調査で既に把握されていたはずだが、
「deny から外す」という対応が「機能していた無効ルールを無害化した」のか「そもそも何も
変えていない」のかを見誤り、`--permission-mode auto` の効果を過大評価したまま #362 を
完了報告していた。読み取り専用のツール実行を許可するには、`deny` を空にするだけでは
不十分で、**allow 側に明示的な Exec プレフィックスを追加する必要がある**という、glob ベース
の直感（`Read(**)`/`Write(**)` から `Exec(**)` も同様に効くはずという類推）がそもそも
このパーミッションシステムに通用しないことが根本原因だった。
