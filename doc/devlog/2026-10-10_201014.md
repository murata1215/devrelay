# 2026-10-10 20:10 JST ｜ サイクル1.0: 高辻ナレッジ — 会話ターンの embedding とハイブリッド検索

## 要求

会話ターン（AI 応答＋直前の人間入力）を検索可能なナレッジ資産として蓄積したい。新テーブル
`KnowledgeChunk` を作り、キーワード ILIKE と pgvector のハイブリッド検索を MCP
`search_knowledge`（全プロジェクト横断）として公開する。本サイクル（仕上げ回）はコード・DB・
バックフィルはすべて前 submission で完了済みで、devlog・changelog への記録と git への反映
だけが残っていた。

## 実行

`KnowledgeChunk` に Prisma 14 列 + raw SQL の `embedding vector(1536)` を追加し、HNSW 索引
（`m=16, ef_construction=64`）を手書き DDL で適用した。チャンク化（`knowledge-chunker.ts`）・
ハイブリッド検索（`knowledge-rank.ts`、RRF k=60）・MCP `search_knowledge`・
`GET /api/knowledge/search`・`knowledge:backfill` CLI を実装し、テスト 855/855 PASS
（既存 790 ＋ 新規 65）を確認した。その後 `knowledge:backfill` で全ユーザーの既存会話を
バックフィルし、Phase A `scanned=11511 created=11330 chunksCreated=13189
skippedExisting=124 skippedIneligible=57`、Phase B `processed=10314 done=10314 failed=0
skippedNoKey=2922` を記録。送信 20,624,903 文字 / 推定 10,312,452 トークン / 推定コスト
$0.2062（text-embedding-3-small）。

## 発見

- `prisma migrate dev` / `prisma db push` がどちらも使えず手書き DDL が正式経路になった。
  `db push` は schema.prisma に書けない `embedding` 列を「スキーマに無い列」と見なして
  DROP COLUMN することを `prisma migrate diff` で実証した
- exec ターン実行中に Agent 自己更新が走り AI 子プロセスが kill される事故が発生し、
  前サイクル（`cmv250bf60a8byut2sxd9eona`）が中断した。再現条件と対策案を
  `doc/issues.md` に起票した
- バックフィル実行時、`cd X && nohup node Y & disown` が `(cd X && nohup node Y) &` と
  解釈される bash の優先順位の罠により、プロセスが 2 本起動した。Phase B 開始前に
  片方を kill して収束させ（`...ABORTED-duplicate.log`、Phase A 6,200 ターンで中断）、
  重複 0・二重課金なしで完走した
- 前 submission では AI がバックフィル完了（Phase B 完走）を待たずにターンを終了し、
  devlog・changelog への記録と git へのコミット・push が本サイクルへ持ち越しになった
