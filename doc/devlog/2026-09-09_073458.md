## 要求
`get_conversation_history` の本文切り詰めが先頭 2000 文字固定で、exec 完了報告の末尾（commit hash /
push 結果）が読めない問題（#378/#379 で2回連続発生）。`get_build_status` にも同様の末尾情報が無い。
apps/server のみのスコープで `tail: boolean` 入力と `get_build_status.tail` フィールドを追加する。
プランファイル: `curious-rolling-fog.md`。

## 実行
新規外部 import ゼロの純関数モジュール `apps/server/src/services/content-truncate.ts`
（`truncateOnLineBoundary(text, maxLength, keep)`）を追加。`keep`（残す側）と `truncatedSide`
（捨てた側、逆の関係）を JSDoc とテストで固定。`tools.ts` の `get_conversation_history` に
`tail: boolean` 入力を追加し、ローカル定数 `MAX_CONTENT_LENGTH` を削除して新モジュールの
`CONVERSATION_MAX_CONTENT_LENGTH`（2000、値不変）に統一。`get_build_status` は `latestMsg`
クエリを `buildLog` 検索より前に移動（`select: { content: true }` で絞り込み、他分岐の
無駄な列取得も削減）し、`BUILD_STATUS_TAIL_LENGTH`（1500、固定定数・新規入力パラメータにはしない）
で末尾を切り出す `tail` フィールドをメッセージが存在する全分岐（buildLog あり / progress 進行中 /
fallback done）に追加。`summary`・`truncated`・`stopReason` 等の既存フィールドは無変更。
