# 2026-09-09 12:03 JST ｜ 端末モード（PTY）が Claude Code の新しい信頼確認ダイアログで無応答になる問題の修正（#382）

## 要求

Windows 機の端末インタフェースモード（terminalMode）セッションで、Claude からの応答が一切返らない不具合の報告。
ユーザー添付ログ `20260909_113428_terminal-cmtth1u6t017ab1mdvty44se2.log`
（実体 `%APPDATA%\devrelay\logs\terminal-<sessionId>.log`、2542 bytes / 4 行）を
`@xterm/headless` 相当に描画すると、Claude Code のフォルダ信頼確認ダイアログが
2 回描画されたまま何も応答されず EOF になっていた。

```
Accessing workspace:
C:\Users\fwjg2\AndroidStudioProjects\TestClock

Quick safety check: Is this a project you created or one you trust? ...
Claude Code'll be able to read, edit, and execute files here.
Security guide
❯ No, exit
  Yes, I trust this folder
Enter to confirm · Esc to cancel
```

従来（`terminal-parser.ts` の JSDoc 前提）は `❯ 1. Yes, I trust this folder` / `  2. No, exit`
の番号付き・Yes 先頭だったが、新しい Claude Code は番号なし・No, exit が先頭（既定選択）に変わっていた。

## 実行

プランモードで根本原因を 2 点特定した:

1. **検出できない**: `detectStartupChoicePrompt()` が番号付き選択肢
   （`^\s*[❯>]?\s*1\.\s+\S`）を必須条件にしており、番号なしダイアログに一致しない →
   承認カードが転送されない → `detectPromptReady()` も false のまま 15 秒の起動タイムアウトで PTY が kill される。
2. **検出を緩めるだけでは危険**: 応答処理・フォールバックが「option 1 = 既定選択」の絶対位置指定
   （option 1 → Enter のみ、option N → `↓` × (N-1) + Enter）だったため、新レイアウトで Enter を送ると
   意図せず `No, exit`（終了）を選んでしまう。

承認を得て以下を実装:

- **`agents/linux/src/services/terminal-parser.ts`**:
  - `extractChoicePrompt()` の戻り値に `cursorIndex`（`❯` が乗っている options 配列内位置、0-based）を追加。
  - 番号付きシーケンスが取れない場合のフォールバックとして `extractCursorListOptions()` を新設。
    カーソル行のテキスト開始列を基準に上下の兄弟行（同じ列から始まる非空行）を収集し、
    空行・セパレータ（`─` `╭` `╰` `⏵`）・`Enter to ` 指示行・`●` で停止。列基準にすることで
    見出し `Security guide`（列 2）や指示行 `Enter to confirm · Esc to cancel`（列 2）を
    選択肢テキスト（列 4）に混入させない。
  - `detectStartupChoicePrompt()` を `hasInstruction && (hasNumberedOptions || hasCursorList)` に拡張。
- **`agents/linux/src/services/terminal-runner.ts`**:
  - `answerChoice(ptyProcess, cursorIndex, targetIndex)` を新設し、`delta = targetIndex - cursorIndex`
    から `\x1B[B`/`\x1B[A` の相対移動 + 100ms 後 `\r` を送る方式に統一。startup choice / mid-session choice /
    bypass permissions 自動承認の 3 経路すべてをこれに置き換え。
  - `findSafeAutoChoiceIndex(options)` を新設し、`onChoiceRequest` 未配線時のフォールバックを
    「option 1 自動選択」から「`trust this folder` 等の意味的に安全な選択肢のみ自動選択、
    見つからなければ何も押さない」に変更（`No, exit` を誤って押すより安全側）。
  - 起動タイムアウトの診断メッセージに `detectTrustPrompt()`（既存だが呼び出し元ゼロだった安全網）による
    「フォルダ信頼確認が未応答のまま残っている」旨の警告を追加。
- **新規 `agents/linux/tests/terminal-parser.test.mjs`**（13 件）: 新レイアウト（実障害ログの実文面）・
  旧番号付きレイアウト（回帰防止）・bypass permissions・AskUserQuestion 形式（#228/#232 回帰防止）・
  誤検出防止・スクロールバック優先順位（#232 回帰防止）を収録。

## 発見

- `detectTrustPrompt()`（`terminal-parser.ts`）は以前から新旧両レイアウトのテキストに一致していたが、
  呼び出し元がゼロだった（trust 専用 auto-confirm を汎用経路へ統合した際の残骸）。今回、起動タイムアウト
  診断の安全網として初めて配線した。
- `terminal-runner.ts` / `terminal-parser.ts` は `agents/linux` にのみ存在し、Windows CLI Agent もこのコードを
  使う（`agents/windows` の Electron GUI 版とは別物）。修正は対象 Windows 機の `u`（Agent 更新）のみで届く。
- ログの二重描画は `flags: 'a'` の追記ログに同一 sessionId の 2 回の spawn（起動タイムアウトによる再試行）が
  積み重なった結果であり、今回の修正で検出・応答ができるようになれば再発しない見込み。

反映は `apps/server` 無変更のため DB マイグレーション・`pm2 restart` 不要。対象 Windows 機で `u` のみで良い。
