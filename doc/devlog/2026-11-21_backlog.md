# 2026-11-21 Backlog 連携（課題の選択・内容確認・状態変更）

## 背景

Backlog の課題を DevRelay のスレッドで進めたい。想定する流れ:

> 人間「未対応一覧だして」→ AI 一覧 → 人間「この課題の内容は？」→ AI が本文とリポジトリを読んで要約
> → 人間「やろう」→ AI が処理中に → 修正・テスト → AI「テスト中にしますか？」→ OK → 結合テストに
> → 人間「コミットして」→ AI がコミットしてリリース待ちに

問題は、状態（ステータス）がプロジェクトごとに違うこと（LAFIT は 7 状態、TISA 標準は 4 状態。ID も名前も違う）。

## 決めたこと（ユーザー決定）

- **API キーは人ごと**。Backlog のキーは発行者と同じ権限で動くので、本人が見られないプロジェクトには AI も触れない。更新履歴にも本人名が残る
- **使ってよいプロジェクトを本人が選ぶ**（DevRelay 側の許可リスト。一覧・閲覧・状態変更のすべてに効く）
- **段階 → 状態の対応をプロジェクトごとに持つ**。段階は start（着手）/ test（テスト）/ done（完了報告）の 3 つ。名前から自動推測し、設定画面で直せる。「なし」にした段階は推測で埋め戻さない
- 案件欄の横の `Backlog▼` で課題を選ぶ → 案件 = 課題キー（キーだけ）、右に件名と状態。状態クリックで人間が変更できる
- プランモード中も、同意があれば状態を変えてよい
- 一覧の既定は「自分が担当の未対応＋着手中」
- AI が着手（start）にしたら、スレッドの案件に課題キーを自動で入れる（空か、すでに課題キーのときだけ。手で付けた案件名は残す）

| 段階 | LAFIT（7 状態） | TISA 標準（4 状態） |
|---|---|---|
| 着手 | 処理中 | 処理中 |
| テスト | 結合テスト | なし |
| 完了報告 | リリース待ち | 処理済み |

## 実装

### サーバー
- `services/backlog-rules.ts`（純関数・テスト対象）: `guessPhaseMap` / `resolveTargetStatus` / `normalizeBacklogSpace`（`*.backlog.jp|com`・`*.backlogtool.com` 以外は拒否＝キーを任意ホストへ送らない）/ `sanitizeProjectsSetting` / `isBacklogIssueKey`
- `services/backlog.ts`: Backlog API v2 呼び出し（`fetch`。社内プロキシは既存の globalDispatcher が効く）、状態一覧 5 分・自分 30 分のメモリキャッシュ、`listIssues` / `getIssue` / `moveIssue`（並び順で前に戻る変更は `force` が無い限り 409）/ `buildBacklogPromptLine`
- `routes/backlog-api.ts`:
  - ログイン必須: `GET/PUT /api/backlog/config`、`GET /api/backlog/projects`、`GET /api/backlog/projects/:key/statuses`、`GET /api/backlog/issues`、`GET /api/backlog/issues/:key`、`POST /api/backlog/issues/:key/status`
  - マシントークン（スキル用）: `GET /api/agent/backlog/issues`、`GET /api/agent/backlog/issues/:key`、`GET /api/agent/backlog/projects/:key/statuses`、`POST /api/agent/backlog/issues/:key/move`、`GET /api/agent/backlog/current`。`format=text` で平文を返す（jq の無い Windows 端末向け）。move のパラメータは本文・クエリのどちらでも可
- `user-settings.ts`: `backlog_api_key`（暗号化）/ `backlog_space` / `backlog_projects`（JSON）。`GET /api/settings` で `backlog_api_key` を伏せる
- `agent-manager.ts` `sendPromptToAgent`: 案件が課題キーなら【Backlog課題】1 行をプロンプト先頭へ（Backlog は 3 秒タイムアウト、失敗時はキーだけ。端末モード・statePolicy あり・引継ぎターンは付けない）

### Agent（linux。Windows 端末もこれ）
- `skill-manager.ts`: スキル `devrelay-backlog`（`scripts/backlog.sh`）。値は一時ファイル経由で `curl --data-urlencode name@file` に渡す
  - **Git bash 版 curl（mingw）は引数の日本語を Shift_JIS に変えてしまう**ため（実測: `未対応` → `%96%a2%91%ce%89%9e`）。さらに mingw curl は `/tmp/…` を読めないので `cygpath -m` で `C:/…` に直す（WSL では cygpath が無いのでそのまま）
- `plan-permission.ts`（linux/macos）: `isBacklogSkillInvocation()` — `bash <~ か絶対パス>/.claude/skills/devrelay-backlog/scripts/backlog.sh …` をプランモードでも許可（相対パス・`..` 混じり・別スクリプト・リダイレクト・複合コマンドは不可）
- macOS 版 skill-manager は linux 版より大きく遅れているため、スキル本体は linux 版のみ（macOS 端末で使う場合は別途）

### WebUI
- `components/BacklogIssuePicker.tsx`: `BacklogPickButton`（課題一覧ダイアログ）/ `BacklogIssueBadge`（件名・状態・状態変更メニュー。画面復帰時と 1 分ごとに取り直す）
- `components/CaseTagBar.tsx`: ボタンとバッジを組み込み。案件は画面復帰時と 20 秒ごとに静かに取り直す（AI の move start を反映するため）
- `components/BacklogSettingsSection.tsx`: 設定画面「🔗 連携」タブ先頭の「Backlog 連携」欄（当初 AI タブに置いたが、AI の設定ではないため同日に連携タブへ移した）

## 追加: 1 人で複数の Backlog スペース（接続）

ユーザー要望「1 台のエージェントで色々な Backlog サーバーにアクセスしたい。devrelay.io ではお客様ごとに設定が要るので個人設定にあった方がよい」。

- 個人設定に**接続**を何件でも持てる（接続 = スペース・API キー・使うプロジェクト・段階の対応）。保存は UserSettings `backlog_connections`（JSON 全体を暗号化、上限 20 件）。`GET /api/settings` には出さない
- 旧形式（`backlog_space` / `backlog_api_key` / `backlog_projects`）は接続 `c1` として読み替え、次の保存で新形式へ移して旧キーは消す（移行作業なし）
- 課題キーのプロジェクトキーと、各接続でチェックしたプロジェクトを照らして接続を自動で決める（`pickConnectionForProject`）。別スペースに同じプロジェクトキーがあって両方チェックした場合だけ 409（どちらかのチェックを外すよう案内）
- 一覧は全接続を並行して取り、更新順に混ぜる。1 接続のエラーは `errors` に入れて残りは返す
- API: `POST/PUT/DELETE /api/backlog/connections[/:id]`、`GET /api/backlog/connections/:id/projects`、`…/projects/:key/statuses`（旧 `PUT /api/backlog/config`・`/api/backlog/projects*` は廃止）
- `DEVRELAY_BACKLOG_SPACE` は「接続を追加」の初期値（と旧形式の読み替え）にだけ使う。devrelay.io では未設定でよい
- WebUI: 設定は接続ごとのカード＋「接続を追加」。課題一覧のプロジェクト絞り込みは接続 2 件以上で「スペース / プロジェクト名」、行にスペース名
- スキル: `list --space <スペース>` を追加（show/move は課題キーから自動）

## 追加: 課題一覧の初期表示を「自分＋担当なし」に

ユーザー要望「最初に開いたとき自分のみ出るが、自分と担当なしを出してほしい」。

- 担当の絞り込み `assignee=mine_unassigned|mine|unassigned|everyone`（既定 `mine_unassigned`。旧 `everyone=1` は「全員」として受ける）
- Backlog API に「担当者なし」の指定が無いため、`mine` 以外は担当者を指定せず最大 100 件（更新の新しい順）取ってサーバー側で絞る（`filterByAssignee`）。漏れるのは古いものだけ
- WebUI: 「全員分」チェックボックス → 担当プルダウン（自分＋担当なし / 自分のみ / 担当なしのみ / 全員）。担当なしの課題は枠付きで「担当なし」
- スキル: `list` の既定も同じ。`--mine` / `--unassigned` を追加（`--all` は従来どおり全員）

## 追加: 案件から外す ✕ と、一覧で中身を確認してから取得

ユーザー要望「間違えて取ったとき消したい」「明細を押したら中身を確認、OK なら案件として取得」。

- 状態バッジの右に ✕（確認ダイアログ → 案件欄を空にする。Backlog の状態は変えない。取得エラー時も出す）
- 課題一覧: 行を押すとすぐ下に中身（種別・登録者・登録日・期限・担当・本文を改行どおり、長文は枠内スクロール）が開く。
  「この課題を案件にする」で初めて取得。もう一度押す・「閉じる」で畳む。中身は一覧を開いている間キャッシュ
- サーバー: `GET /api/backlog/issues/:key?detail=1` で本文・種別・登録者・登録日・期限を追加で返す（既存 `getIssue()` を流用、コメントは返さない）
- `CaseTagBar` の保存処理を `saveValue()` に共通化（入力欄確定・課題選択・✕）

## 修正: スキルの move が会社サーバーで 411 Length Required

実機テスト（ATG_39_P_0002-1174）で `current` / `show` / `statuses` は通ったが `move` だけ失敗。

- 原因: `backlog.sh` は値を `-G` で URL に載せるため POST の本文が空。curl は空本文に Content-Length を付けず、
  前段の IIS（`service.internal.atg.co.jp/tsinternal/devrelay`）が 411 で拒否する。ローカルのエコーサーバーでは再現しなかった
- 対処: `call()` で POST のときだけ `-H "Content-Length: 0"` を付ける（値は URL のまま＝日本語対策は不変、サーバー変更なし）
- 確認: 実サーバーへ無効トークンで POST → ヘッダ無し 411 / ヘッダ有り 401「マシントークンが無効です」（前段を通過）。
  生成スクリプトはエコーサーバーで POST のみ `content-length=0`、GET は付かないことを確認
- 反映は各端末の `u`（サーバー再起動不要）
