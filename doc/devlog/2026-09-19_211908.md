# 2026-09-19 21:19 JST ｜ 調査: `ask` 経路をゲーム席用の素の completion API として使えるかの前提確認（read-only）

別プロジェクト dangou-card（LLM 対戦ゲーム）から、DevRelay の `ask` 経路経由で
Claude Code（Max サブスク）/ Codex（ChatGPT サブスク）を 1 席のプレイヤーとして参加させたいという
依頼を受け、既存の `ask`（cross-project query）にどこまで乗るか・何が足りないかを確定させるための
read-only 調査を実施した。コード変更は一切行わず、成果物は調査レポートと本 devlog のみ。

## 調査方法

`apps/server/src/routes/document-api.ts`（ask-member ハンドラ本体）、
`apps/server/src/services/{agent-manager,permission-policy,cross-query-guard,user-settings}.ts`、
`agents/linux/src/services/{connection,ai-runner,session-scope,output-collector}.ts`、
Claude Agent SDK の型定義（`@anthropic-ai/claude-agent-sdk` の `sdk.d.ts`）、
`~/.claude/skills/devrelay-ask-member/scripts/ask.sh` を、3並列の探索エージェントによる粗調査 →
主要な相違点（サーバー側タイムアウトの実値、履歴注入の有無）を自分で再読して裏取り、という
2段階で確認した。

## 見つかったこと（詳細は `doc/analysis/ask_raw_mode_investigation.md` 参照）

- **HTTP 入口**: `POST /api/agent/ask-member` は完全同期（`{ answer: string }` を返す）。
  ask.sh 側 curl タイムアウトが実質の上限（600秒）。サーバー側 `executeCrossProjectQuery()` の
  既定タイムアウトは `agent-manager.ts:1382` で **12時間**（JSDoc は「デフォルト5分」と書かれており
  コメントと実装が食い違っている＝副産物1件目）。
- **プロンプト注入**: ask は ephemeral セッション（`crossquery_` プレフィックス）のため
  会話履歴・resume は自動的に無効（既に良い設計）。一方 Agreement は文字列連結ではなく
  Claude SDK の `settingSources: ['user','project']`（`ai-runner.ts:939`）経由で CLAUDE.md が
  読み込まれる形で混入しており、ask 専用に無効化する手段が無い。plan モード指示・
  `.devrelay-output/` 指示も無条件で付き、個別無効化フラグは存在しない。
  副産物として `storageContextPrompt`/`workStatePrompt`（`connection.ts:1078-1093`）が
  `isEphemeral` ガードから漏れており、対象プロジェクトの状態が ask のプロンプトに
  混入し得る箇所を発見した（副産物2件目）。
- **モデル/ツール**: ask は plan 側モデル固定（呼び出し単位の指定不可）、
  全ツール無効化の手段なし（`allowedTools: []` は無視され既定 read-only 一式にフォールバック）、
  Claude SDK には `systemPrompt` 完全置換オプションが存在するが DevRelay 未使用、Codex は
  system prompt 相当のフラグ自体が未配線。
- **レート制限**（`document-api.ts:35-46`）: ask は同一ターゲット8回/5分・同時実行1件まで。
  ゲーム要件（ピーク15回/5分、150コール/試合）は前者に約2倍抵触し、構造的な壁と判定した。

## 判定

**不可**（現状の ask をそのままゲーム席にはできない）。プロンプト構造（層A）と
流量制御（層B）の両方が独立したブロッカーで、どちらも設定変更では回避できない。

## 提示した最小追加実装案（未実装・レポートのみ）

ユーザーからの承認ノートで指定された方針に従い、「`ask` に `raw` フラグを足す」案は不採用とし、
**専用エンドポイント `POST /api/agent/raw-completion` + 専用セッション接頭辞 `raw_` の新設**を
1案として記載した。既存 `crossquery_`/`teamexec_` のレート制限・カウント関数・
`permission-policy.ts`/`cross-query-guard.ts` の判定順序には一切触れず、
`ai-runner.ts` の `usePlanMode`/`skipPermissions` 分岐とは独立した第三の分岐として実装する設計とし、
影響ファイルと概算行数（サーバー側 +140〜160行、Agent 3OS合計 +220〜280行）を記載した。
Codex のネイティブ system prompt 置換フラグの有無、Codex 実行時の usage 記録の可否は
実機未確認のためレポート内に「要実測」として明記した。
