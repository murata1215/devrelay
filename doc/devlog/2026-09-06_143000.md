# 2026-09-06_143000 #367 WebUI 管理者メニュー（Settings→System タブ・サーバー再起動）をシステム管理者のみに限定

## 要求

ユーザーが実チャットで「僕以外の人もサーバー再起動できると思う」と報告。

## 調査（planモード）

- `POST /api/services/restart/server` を実測したところ `authenticate` のみでロール/所有者チェックが皆無であることを確認、
  `SettingsPage.tsx` の System タブも全ユーザーに常時表示されていることを確認。
- 「システム管理者」を `OrganizationMember.role`（テナント内権限）と同一視できないと判断: 唯一の組織の admin は無関係な顧客テナント
  管理者であり、実運用者自身は `OrganizationMember` 行を持たないため、組織ロールでは両方向に誤る。
- 採用方針: 環境変数allowlist `DEVRELAY_SYSTEM_ADMIN_EMAILS`（カンマ区切り、未設定/空なら全員 false = fail-closed）。
  `.env` 編集権限と付与権限が一致するため権限昇格が構造的に起きない設計。

## 実行（execモード）

1. 新規 `apps/server/src/services/system-admin.ts`（外部importゼロ純関数 `parseSystemAdminEmails`/`isSystemAdminEmail`/
   `getSystemAdminAllowlist`/`requireSystemAdmin`）+ `tests/system-admin.test.mjs`（23件）を追加。
2. `api.ts` の2エンドポイントに `requireSystemAdmin(request as unknown as MinimalRequest, reply)` ガードを追加
   （FastifyRequestは`user`を型宣言せずMinimalRequestとの構造的キャストに`unknown`経由が必要、ビルドで発覚し修正）。
3. `POST /api/services/restart/agent`（Agentをpm2登録禁止のこの機体では常に失敗し握りつぶして嘘の成功を返していた）を
   ハンドラごと削除、`GET /api/services/status`からAgentプローブも削除。
4. `auth.ts`の`formatUser()`単一情報源に`isSystemAdmin`追加（register/login/me/Google OAuth callbackの4経路に自動反映）。
5. `apps/web/src/lib/api.ts`の`User`に`isSystemAdmin?`追加、`services.restartAgent()`削除、
   `ServiceStatus`を`{server}`のみに簡素化。
6. `SettingsPage.tsx`: `visibleTabs`（`isSystemAdmin`でSystemタブを`useMemo`フィルタ）を導入し
   `activeTab`計算・矢印キー操作・タブ一覧描画をすべて`SETTINGS_TABS`から差し替え、Systemパネルを`hidden`属性ではなく
   `{isSystemAdmin && (...)}`でDOM自体から除外、`handleRestartAgent`/`handleRestartBoth`/`restartingAgent`を削除し
   `handleRestartServer`のみ残置、`services.status()`を`loadSettings`の`Promise.all`から外し`isSystemAdmin`依存の
   専用`useEffect`に分離（非管理者が毎回403を踏まないため）。
7. `/api/machines/:id/restart`（既存の所有者スコープ済みAgent再起動、正しい経路）・`Layout.tsx`は無変更。

## 発見

- 「システム管理者」と「組織ロール」は別軸であり、既存の`OrganizationMember.role`を流用すると
  実運用者自身が管理者になれない/無関係なテナント管理者が全権を持つという二重の誤りが生じることが分かった。
