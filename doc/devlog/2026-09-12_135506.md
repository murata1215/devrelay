# Lite L5.0.1: 承認カードにツールの実行内容を表示（web のみ）

## 背景

L5（`3c726c0`）で Lite の承認カード（`LiteApprovalCard.tsx`）は承認/拒否ボタンが押せるようになったが、
描画していたのはツール名（`prompt.title ?? prompt.toolName`）と定型文のみで、`toolInput` を一切
描画していなかった。つまり Lite のユーザーは「Bash」としか書かれていないカードに対して実行を許可する
状態で、`rm -rf` なのか `ls` なのかが見えなかった。L5 でボタンを有効化したことで実害が生じうる状態
だったため、classic と同じ情報を Lite にも表示する。

## 実装方針

classic（`ChatPage.tsx` の `ToolApprovalCard` / `formatInput()`、428-444行）が読むフィールドと
優先順位を実測確認したうえで、**同じフィールド・同じ優先順位**を Lite 側にも適用した。推測で
別フィールドを使うことはしていない。

- `Bash` → `toolInput.command`
- `Read` / `Write` / `Edit` / `MultiEdit` → `toolInput.file_path`
- `NotebookEdit`（classic には無いが同じ意味論なので追加） → `toolInput.notebook_path`、
  無ければ `toolInput.file_path` にフォールバック
- `Glob` → `toolInput.pattern`
- `Grep` → `toolInput.pattern`（+ `path` があれば `` `${pattern} in ${path}` ``、classic と同一文字列生成）
- 上記いずれにも該当しない → `JSON.stringify(toolInput)`（classic は 120 文字で切り詰め、
  Lite は `LITE_APPROVAL_JSON_MAX_CHARS`=400 で切り詰め）

`Edit` の `old_string`/`new_string` 差分は要件どおり出さない（`file_path` のみ表示）。人間の承認
ノート指示により、`MultiEdit` は classic の `formatInput()` に分岐が無くても `toolInput.file_path`
が文字列なら `path` として表示するようにした（テストで固定済み）。

## 変更内容

### `apps/web/src/components/lite/lite-shell-rules.ts`（§17 を純追加）

外部 import ゼロの方針を維持するため、`summarizeApprovalInput()` の引数は `ToolApprovalPrompt` を
直接 import せず `{ toolName?: unknown; toolInput?: unknown }` という構造型で受け取る（構造的に
`ToolApprovalPrompt` を渡してもそのまま適合する）。

- `summarizeApprovalInput(prompt, limits?)` — 全分岐 fail-open。`toolInput` が非 null のプレーン
  オブジェクト（配列でない）でなければ即 `null`。JSON フォールバックは循環参照等で `throw` しうる
  ため `try/catch` で囲み、失敗時も `null`。空オブジェクト `{}` の JSON 化（`'{}'`)は意味のある
  表示にならないため `null` 扱いにした。
- `LiteApprovalInputSummary { kind, text, truncated }` — `text` は上限で切り詰め済み。省略記号
  （`…`）は関数側では付与せず、描画側（カード）の責務にした。
- 上限定数: `LITE_APPROVAL_INPUT_MAX_CHARS`（既定 2000、command/path/pattern 用）、
  `LITE_APPROVAL_JSON_MAX_CHARS`（既定 400、JSON フォールバック用）。

### `apps/web/src/components/lite/LiteApprovalCard.tsx`

- `summarizeApprovalInput` を値 import。
- `prompt.description` ブロックの直後・定型文ブロックの直前に、`summary` があれば
  `font-mono` + `whitespace-pre-wrap` + `break-all` + `max-h-40 overflow-y-auto` のブロックを追加し
  `summary.text`（+ 切り詰め時は `…`）を描画。
- JSX のテキスト子要素として描画するのみ（`dangerouslySetInnerHTML` は使わず、markdown/HTML 解釈
  は行わない）。
- `useState` は追加せず、L5 で確立した「内部 state を一切持たない受動コンポーネント」性質を維持。
  `onRespond` / `status` の分岐ロジックは無変更。

### テスト

- `apps/web/tests/lite-shell-rules.test.mjs`: `summarizeApprovalInput` の describe を新設し、
  Bash/Read/Write/Edit/MultiEdit/NotebookEdit/Glob/Grep/未知ツールの各分岐、`toolInput` が
  null/undefined/配列/文字列/`{}` の fail-open、循環参照での非 throw、切り詰め境界（`maxChars`
  ちょうど / 超過）、`limits` 上書き、上限定数の型を検証（+29 ケース）。
- `apps/web/tests/lite-source-guards.test.mjs`: `LiteApprovalCard.tsx` に対する新規 describe を追加
  — `summarizeApprovalInput(` の呼び出し配線固定、`dangerouslySetInnerHTML` 不在の恒久固定、
  `useState`/`useReducer` 不在（受動コンポーネント性質の恒久固定）。CJK リテラル不在チェックは
  既存の全 Lite ファイル共通ガード（コメント除去後）がそのまま `LiteApprovalCard.tsx` をカバーして
  いるため重複追加しなかった（本サイクルでも日本語リテラルは追加していない・`messages.ts` 無変更）。
