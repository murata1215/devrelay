## 人間側の反映手順

1. ALTER 3本 + INDEX 作成（すべて nullable・DEFAULT なし = 稼働中でも安全）:

```sql
ALTER TABLE "Session" ADD COLUMN "title" TEXT;
ALTER TABLE "Session" ADD COLUMN "lastActiveAt" TIMESTAMP(3);
ALTER TABLE "Session" ADD COLUMN "agentScopeId" TEXT;
CREATE INDEX "Session_projectId_status_lastActiveAt_idx"
  ON "Session"("projectId", "status", "lastActiveAt");
```

2. 検証 SQL（カラム3行 / index 1行 / バックフィルされていないことの3点確認）:

```sql
SELECT column_name FROM information_schema.columns
  WHERE table_name = 'Session' AND column_name IN ('title', 'lastActiveAt', 'agentScopeId');
-- 3 行

SELECT indexname FROM pg_indexes
  WHERE tablename = 'Session' AND indexname = 'Session_projectId_status_lastActiveAt_idx';
-- 1 行

SELECT count(*) FROM "Session" WHERE "agentScopeId" IS NOT NULL;
-- 0 件（適用直後は必ず0。以後、新規スレッド作成分のみ増える）
```

3. `cd apps/server && npx prisma generate`（本サイクルで既に実行済みだが、DB反映後の環境では再実行推奨）
4. `pnpm build`
