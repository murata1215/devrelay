## 要求

ユーザーから `w,プッシュして` の依頼。まず現状を実測したところ `git status --short` は空
（コード変更は残っていない）で、直前の #362 サイクル（`fix(devin): plan-mode silent
truncation + .svn file-watch flood`, commit `143d349`）が **未 push のまま `origin/main` に
対して ahead 1** の状態だった。`doc/changelog.md`・`rules/project.md` は `143d349` に
含まれ commit 済みだったが、`doc/devlog/`（1 サイクル1ファイル+`INDEX.md`索引の運用）と
`README.md` への反映が漏れていたため、本サイクルはこの2点を仕上げてから push する。

## 実行

1. `README.md` の Devin Plan Mode Read-Only Enforcement の bullet を更新——`deny` の記述が
   #362 以前（`["Write(**)","Exec(**)"]`）のまま古くなっていたのを `deny: ["Write(**)"]` のみに
   訂正し、`--permission-mode auto` の多層防御・キルスイッチ `DEVRELAY_DEVIN_PLAN_EXEC_DENY=1`・
   `Exec(**)` を外した理由（DevRelay 自身の bash 実体スキルを巻き添えにしていた）を追記。
2. `README.md` の #361 bullet の直後に #362 専用の新規 bullet を追加——`endedWithoutAnswer()`
   による無音途中終了の検知と `devin.planTurnTruncated`、`devin-file-watch.ts` の
   `isNoisyChangedPath()`（`.svn`/`.hg`/`.bzr`/`CVS` 除外）とターン通知上限
   （`DEVRELAY_DEVIN_FILEWATCH_MAX`、既定20）+ `devin.fileWatchTruncated` を明記。
3. 本ファイル（`doc/devlog/2026-09-05_182355.md`）を新規作成し、`doc/devlog/INDEX.md` に
   索引1行を追記。
4. `git add README.md doc/devlog/2026-09-05_182355.md doc/devlog/INDEX.md` → commit →
   `git push origin main`（`143d349` と本 docs コミットの2つを同時に push）。
