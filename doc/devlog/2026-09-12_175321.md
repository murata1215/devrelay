# classic: Servers / Agents サイドバーを右レールに移し、折りたためるようにする（web のみ）

- 日時: 2026-09-12_175321 (TZ=Asia/Tokyo)
- プラン: `temporal-leaping-otter.md`
- スコープ: `apps/web` のみ（`apps/server` / `agents/*` / `packages/*` / `prisma` / Lite（`/lite`、`components/lite/*`）は無変更）

## 背景（なぜやるか）

classic チャット画面（`/`, `ChatPage.tsx`）は左端に Servers / Agents サイドバー（`w-56`=224px）が常時居座っていたが、
実装を読むと `collapsed` は `md:translate-x-0` に上書きされるため **768px 以上では折りたたみが一切効かず常に表示**
されていた。一方 DocPanel（Approvals/Docs/Issues/Plan）は既定で全 OFF のため右側は空。
「常時使わないパネルが左を 224px 食い、右は空いている」状態を解消するため、Servers/Agents を右レールへ移し、
レール全体を折りたたみ可能（永続化）にして、左をスレッド一覧＋チャット本文に充てた。
ロジック変更はせず、レイアウト移動のみ（プランの判断1〜5を参照）。

## 設計判断の要点（プランからの実装差分含む）

1. タブ統合ではなく縦積み（上段 Servers/Agents、下段 DocPanel）。Servers を `docPanelSettings` に結合しない
   （OFF にできてしまうと本体機能のプロジェクト切替が不可能になるため）。
2. `Sidebar` に `variant: 'drawer' | 'rail'` を追加。左サイドバーは `variant="drawer"` として
   モバイルドロワー専用に残す（`md:hidden`、既存の `md:relative md:translate-x-0 md:z-auto` 上書きは撤去）。
   右レール内は `variant="rail"`（overlay なし・X ボタンなし・`fixed`/`translate`/`w-56` なし）。
   2 インスタンス同時マウントだが `Sidebar` は API 呼び出しゼロの純 props 駆動なので二重フェッチは発生しない。
3. 幅 state・`handleResizeStart`・リサイズ中オーバーレイ・ハンドル div を DocPanel から `RightRail` へ移設。
   localStorage キー `devrelay-panel-width`・既定 208・clamp 160..600 はそのまま維持（保存幅を破壊しない）。
4. DocPanel の `hidden lg:flex` は DocPanel 自身の `<aside>` からではなく **RightRail 内の DocPanel ラッパー**
   に付け直し、≥1024px の可視性を完全保存。Servers セクションは `md:` から見える。
5. 気付き方は「バッジ」のみ（自動展開なし）。折りたたみストリップに赤丸＋件数（9+ で打ち切り）。
   ソースは `toolApprovals` の `status === 'pending'` 件数（`approvalHistory` の `'auto'` は含めない）。

**プランからの実装差分**: `resolveSidebarShellClass(variant)` はプラン記載どおり `-translate-x-full` の
分岐までは持たず、**静的クラスのみ**を返す設計にした（`collapsed` 状態を引数に取らないシグネチャのため）。
折りたたみに応じた `-translate-x-full` / `translate-x-0` の切替は `Sidebar` コンポーネント側の
`drawerTranslateClass` ローカル変数で計算し、`variant === 'drawer'` のときのみ適用する。
テストはこの実際の設計に合わせ、トークン単位で `fixed`/`md:hidden`/`w-56` の有無、
`md:relative`/`md:translate-x-0`/`md:z-auto` の不在（drawer）、`fixed`/`translate`/`w-56` の不在＋`min-h-0`
の存在（rail）を検証する形にした。

また、プラン判断6h（「ヘッダー行を新設しないので 208px 幅を 28px 節約できる」）に従い、`RightRail.tsx` 自体には
折りたたみボタン用の専用ヘッダー行を追加せず、既存の `Sidebar` ヘッダー行に `headerAction?: React.ReactNode` を
追加して rail インスタンスの呼び出し側（`ChatPage.tsx`）でチェブロンボタンを注入する形にした。

## 受け入れる副作用（プランに明記済みのもの、そのまま踏襲）

1. 既定ユーザー全員に右レールが出る（今まで既定では右は空だった）。
2. レールの可視開始幅が lg(1024) → md(768) になる（Servers 部分のみ。DocPanel 部分は ≥1024 を厳密に保存）。
3. 畳んだ状態ではタブバー→サーバー行のドラッグができない（まず展開する運用。自動展開は次サイクル送り）。
4. 上下 50/50 固定（両セクション `flex-1 min-h-0`）。可動スプリッタは次サイクル送り。
5. `devrelay-panel-width` の意味が「DocPanel 幅」→「レール幅」に変わる（キーは据え置き）。
6. 既存の別問題（`ThreadList.tsx` の `md:` 隠し欠落、375px で224px食う件）は同一サイクルで直さず次サイクル送り。
