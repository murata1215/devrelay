# Lite シェル L2: ルーティング + モード切替 + 空シェル（通信は増やさない）

## Context

L0+L1（commit `0848779`）で純ロジック `components/lite/lite-shell-rules.ts` と
`ThreadList` への optional prop `createProjectId?` を追加済み。本サイクル L2 は
`/lite` ルートと従来 UI との切替導線、3 ペインの骨組みまで。
「画面は出る・切替できる・しかし通信は増やさない」に限定する
（WS 接続・メッセージ描画は L3、送信は L4、承認カードは L5）。

参照プラン: `~/.claude/plans/quizzical-zooming-flute.md`
実行プラン: `~/.claude/plans/steady-churning-salamander.md`

## 事前報告した 2 件の衝突と、承認された解決

Plan 提出時、指示どおりに実装できない点が 2 件あることを報告し、ユーザーから明示的な解決指示を受けた。

### B1: ThreadList は行クリックで必ずサーバー POST する

`ThreadList.tsx` の `handleSelect` は無条件で `sessionsApi.switchThread()`（POST）を発行し、
これを抑止する prop が存在しなかった。「＋新規」ボタンも `createProjectId` を渡すと有効化され
`threadsApi.create()`（POST）が飛ぶ。改名ボタンも `sessionsApi.rename()`（PATCH）を発行する。

**承認された解決（案A）**: `ThreadList` に optional prop 3 つを追加する。
`readOnly?` / `onLocalSelect?` / `resolveProjectLabel?`。すべて未指定時は現行と完全同一に落ちる
（`ChatPage.tsx` の呼び出し元は変更ゼロ、diff ゼロ）。行クリックの分岐は新規純関数
`decideThreadRowAction()` に一本化し、`readOnly: true` のときはあらゆる入力で
`'server-switch'` を返さないことをテストで網羅的に固定した（後述）。

### B2: `/` → `/lite` 自動リダイレクトが参照プランと自己矛盾する

指示は「`/` へのアクセス時にモードが lite なら `/lite` へリダイレクト」を要求していたが、
参照プラン `quizzical-zooming-flute.md:131-139` は「`/` からの自動リダイレクトは実装しない」を
明示的に決定済みだった。またリダイレクト実装には `App.tsx` の `/` ルート（`ProtectedContent` 内側）
への変更が必要で、指示自身の「従来 UI への変更は App.tsx のルート 1 ブロック、Layout.tsx の 1 行のみ」
という制約とも矛盾していた。

**承認された解決（B2 は撤回）**: `/` → `/lite` の自動リダイレクトと localStorage によるモード永続化は
**実装しない**。URL を唯一の状態とする。Classic は `/`（〜`/chat`等の既存ルート）、Lite は `/lite`。
双方をヘッダーの明示的なリンクで切り替える（Layout の secondaryNavigation に「Lite UI」リンク、
LiteHeader に「従来 UI に戻る」リンク）。localStorage は一切使わない
（当初計画にあった `utils/lite-ui-mode.ts` は作成しない）。

この撤回により、`App.tsx` への変更は「`/lite` ルート 1 ブロック追加」のみ、
`Layout.tsx` への変更は「secondaryNavigation に 1 行追加」のみに収まった
（`git diff` で実測確認、後述）。

## 通信を増やさないことの確認（L2 の禁止対象）

| 通信 | L2 | 結果 |
|---|---|---|
| `GET /api/threads`（一覧） | 許可 | `ThreadList` の初期取得で発生（従来どおり） |
| `GET /api/projects`（セレクタ） | 許可 | `LitePage` の `useEffect` で発生 |
| `POST /api/threads`（作成） | 禁止 | `readOnly` により「＋新規」が disabled、`handleCreate` 自体もガードで早期 return |
| `POST /api/sessions/:id/switch` | 禁止 | `decideThreadRowAction()` が `readOnly: true` のとき `'server-switch'` を返さない（後述のテストで網羅） |
| `PATCH`（改名） | 禁止 | 改名ボタン自体を非表示化 |
| WebSocket 接続 | 禁止 | `LitePage`/`LiteHeader`/`LiteComposer` はいずれも `useWebSocket` を import せず `new WebSocket` も書かない（静的走査テストで固定） |

## テスト

新規依存ゼロ。`apps/web` は jsdom も testing-library も無いため（`node --test tests/` のみ）、
純関数テスト + ソース静的走査テストの 2 方式で固定した。

### `lite-shell-rules.test.mjs`（追記）

- `decideThreadRowAction`: B1 の核心テスト。`sessionId` × `currentSessionId`（null/undefined/一致/不一致）
  × `switching`（true/false）の全組み合わせで `readOnly: true` のとき `action.kind` が
  `'server-switch'` に一度もならないことを表明。`readOnly: false` では従来どおり `'server-switch'` を
  返すことも併せて固定（従来 UI の非退行）。
- `buildProjectSelectorOptions`: displayName あり/なし、machine 無し、`machine.displayName` あり、
  `online: false`、空配列、並び順保持を検証。
- `containsNamespaceImport` / `containsRawWebSocketConstruction`: 各 3 テストの正例・負例。
- `findForbiddenLiteImports` の一般化: 引数省略時の後方互換 + L2 リストを渡したときの opt-in 挙動。
- `L2_FORBIDDEN_LITE_BINDINGS` / `L2_FORBIDDEN_LITE_MODULES` の内容固定。

### `lite-source-guards.test.mjs`（新規）

`node:fs` で `LitePage.tsx` / `LiteHeader.tsx` / `LiteComposer.tsx` の生ソースを読み、
コンパイル済み純関数で走査する。

1. 恒久リスト（`Layout` / `useOrganization`）のヒットが 0（F5 トリップワイヤ）
2. L2 リスト（`useWebSocket` / `hooks/useWebSocket`）のヒットが 0
3. `new WebSocket` の文字列が現れないこと
4. `import * as` （namespace import）が現れないこと
5. `LitePage.tsx` の `<ThreadList ... />` 使用箇所に `readOnly` が含まれること
   （L3 で `readOnly` を外す際にテストが落ちて気付ける回帰トリップワイヤ）

## E2E テスト手順（人間側、devlog として記録のみ・本サイクルでは未実施）

### Phase B: 従来 UI 無傷（**`/lite` を一度も開かずに**実施）

1. `/chat` でタブ復元・履歴表示・送信・AI 応答受信が従来どおり
2. `ThreadList` の「＋新規」が有効で、作成 → 切替が動く

4. スレッド改名が動く

### Phase C: Lite 単体

6. 歯車メニュー →「Lite UI」→ `/lite` が開き、真っ白にならない
7. `ThreadList` に横断一覧が出る（複数プロジェクトのスレッドが混在）
8. プロジェクトバッジが `displayName` で表示される（`name` ではない）
9. プロジェクトセレクタに `machine.displayName` とオンライン状態が出る
10. DevTools Network を開いた状態でスレッド行をクリック →
    `/switch` と `/api/threads` の POST が 1 件も出ない。行のハイライトだけが移動する
11. 「＋新規」ボタンが disabled
12. DevTools Network の WS タブに新規 WebSocket 接続が 1 本も出ない
13. 「従来 UI に戻る」→ `/chat` に戻り、AI 応答が届く
14. `/lite` → `/chat` → `/lite` を同一タブで数回往復しても 6〜13 が再現する

## L3 への申し送り

1. **WS 二重接続の本番テストは L3 の必須 E2E とする**:
   - 別ブラウザタブで従来 UI（`/chat`）を開いたまま `/lite` を開き、**従来側の応答が途切れない**
   - 同一ブラウザタブで `/lite` ↔ `/chat` を行き来して**両方の応答が届く**
2. B2（`/` → `/lite` 自動リダイレクト、localStorage モード永続化）は本サイクルで撤回済み。
   URL のみを状態とする設計を L3 以降も維持すること。再度リダイレクトを検討する場合は、
   参照プラン `quizzical-zooming-flute.md:131-139` の「実装しない」判断を再度上書きする根拠が
   必要になる。
3. `ThreadList` の `readOnly` を外し、`onLocalSelect` を `sessionsApi.switchThread()` 経由に
   切り替える。`LitePage.tsx` の no-op `onSelect` を実装に差し替える。
   このとき `lite-source-guards.test.mjs` の項目 5（`readOnly` 表明）が落ちるので、テストも
   同時に更新すること。
4. `L2_FORBIDDEN_LITE_BINDINGS` から `useWebSocket` を外す（恒久リスト
   `FORBIDDEN_LITE_BINDINGS` は F5 の防波堤なので触らない）。
5. `useWebSocket` の progress 復元 payload に `sessionId` が無い（F4）ため、
   Lite のルーティングゲートは `shouldRouteToTab()` の fail-open を維持すること。
6. 承認カードの `sessionId` ゲート（サイクル4 申し送り #2）は L5 の後の独立サイクル
   （参照プラン `:268-278`）。
