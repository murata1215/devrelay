# bg-task — バックグラウンド Agent 起動時の「待っています」打ち切りと resume 時の `(No response from AI)` を根治

## 背景

2026-09-20 21:59、`/opt/devrelay` プロジェクト（本番機 `x220-158-18-103`、machineId
`cmm5tpl7y0040f3p2pz056ukv`、Claude Code 2.1.278 / SDK 0.3.278）で raw-completion Phase 2 の
プラン投入（session `cmu9tp9lc00jnhvp1jofjggc8`、Claude session `d8b74ca1`）が次のように壊れた。

1. 22:00:27 — プランモードの AI が Explore を 2 体 **background** で起動し
   （`subagents/*.meta.json` に `"requestShape":"background"`）、
   「Explore 2 体の完了を待っています」で `end_turn`。agent.log: `✅ Complete (60962ms)`。
2. 22:16:35 — 「途中で落ちた？」を送ると `(No response from AI)`。
   agent.log: `✅ Complete (97ms)`、`Context: 0K`、`fullOutput=0 chars`。cost-state の
   `totalAPIDuration` も増えておらず、**モデルは一度も呼ばれていない**。

server ログには `⚠️ No tracker found for session cmu9tp9lc…` も出ていたが、これは
完了後に送られたコンテキスト警告（後述）が捨てられただけで無応答の原因ではない。
`MEMORY.md` は 59KB で auto-compact 問題（#372）とも無関係（実コンテキスト ≈ 62K）。

## 原因（scratchpad で haiku を使い再現、~$0.3）

`claude -p --input-format stream-json --output-format stream-json`（SDK が使う経路）で
バックグラウンド Agent を起動させて観測した。

1. モデルがバックグラウンド Agent を起動して `end_turn` すると、SDK は**その時点で
   `result`（`result_index: 0`）を出す**（対話 CLI・`-p` 引数プロンプトでは result は
   タスク完了まで保留されるが、stream-json 入力モードでは即座に出る）。
   `ai-runner.ts` の result ハンドラは「result は stream-json の終端メッセージ」として
   最初の result で return → SDK プロセス終了 → **サブエージェントは未完のまま殺される**
   （transcript に完了記録なし）。ユーザーには「待っています」で終わった応答だけが届く。
2. その状態で `--resume` すると Claude Code は孤児サブエージェントの
   `<task-notification status=stopped>` を合成し、**モデルを呼ばずに
   `result{num_turns:0, result:'', duration_api_ms:0, subtype:'success'}` を先に出す**。
   `ai-runner.ts` はこれを終端とみなし `fullOutput=0` → `(No response from AI)`。
   プロセスを殺さず読み続けると約 5 秒後に `result_index: 1` として本物の応答が来る。
3. 通知は 2 で消費されるため、もう一度送れば普通に応答する（＝応急処置）。

再現ログ（resume 側）:

```
1.1s system task_notification
1.2s RESULT idx 0 num_turns 0 result ''          ← 従来ここで (No response from AI)
...
6.4s RESULT idx 1 num_turns 2 result 'Agent resumed. ...'
```

sdk.d.ts（0.3.278）の `SDKBackgroundTasksChangedMessage` コメントが、
`background_tasks_changed` を REPLACE セマンティクスの「生きているタスク集合」、
`task_started` / `task_notification` を edge、`ambient: true` を非活動と定義している。
`SDKResultMessage.result_index` のコメントにも「A result held back while background work
finishes」とあり、複数 result が 1 ターンに出ることは SDK の仕様。

## 変更

### 新規 `agents/{linux,macos}/src/services/sdk-background-tasks.ts`（byte-identical、外部 import ゼロ）

- `observeBackgroundTaskEvent(state, m)`: `task_started` で追加、`background_tasks_changed` で
  置き換え（ambient 除外）、`task_notification` で削除（status 不問）。他は無視、例外なし。
- `decideResultDeferral(state, input, config)`: result を終端扱いしてよいか判定。
  - `is_error` → 延期しない（既存エラー経路）
  - 延期回数が `maxDeferrals`（既定 20、env `DEVRELAY_SDK_BG_TASK_MAX_DEFERRALS`）以上 → 延期しない
  - 生きているタスクあり → 延期（`backgroundTasks`）
  - `num_turns === 0` かつ `result` も `fullOutput` も空 → 1 ターン 1 回だけ延期（`emptyResult`）
- `resolveBackgroundTaskConfig(env)`: `idleTimeoutMs`（既定 10 分、env `DEVRELAY_SDK_BG_TASK_IDLE_MS`）。

### `agents/{linux,macos}/src/services/ai-runner.ts`（SDK 経路のみ、+62 行ずつ）

- ループ先頭で毎メッセージ `observeBackgroundTaskEvent()`。
- result ハンドラ: `#377` の stopReason 判定の直後・resume 失敗判定の前に `decideResultDeferral()`。
  延期なら `⏳ Intermediate result deferred (reason=…, result_index=…, pending=[…])` を出して
  `continue`（完了シグナルは送らない。ストリーム済みテキストはそのまま蓄積）。
- 延期中はアイドルタイマーを張り、SDK からメッセージが届くたびに延長。無音が `idleTimeoutMs`
  続いたら `bgIdleTimedOut = true` で `abort()` → catch の先頭（loop-guard の直後、resume 失敗
  判定より前）で手元の `fullOutput` を使って完了を送る（`stopReason='success'`）。
  `finally` でタイマー解除。
- `usageData` / `contextUsage` は途中 result でも記録され、最終 result で上書きされる。

### 変えないもの

PTY 端末モード、Codex / Devin 経路、raw-completion の応答形（`rawOutput` は最終 result の
`fullOutput`）、サーバー、Windows agent。`#355` loop-guard の壁時計上限（既定 120 分）は
延期中もそのまま効く。

## 併発していた別件（本サイクルでは未修正、記録のみ）

- `📊 Context: 408K / 200K tokens (204%)`: `result.usage.cache_read_input_tokens` はターン内の
  全 API 呼び出しの合算（`iterations`）なので、ツール呼び出しが多いターンほど過大になる。
  実コンテキストは最後の assistant メッセージの `cache_read + cache_creation`（≈ 62K）。
- その hard 警告（`⚠️ Context warning sent (204%, hard=true)`）は完了シグナルの**後**に
  `agent:ai:output` で送っているため、サーバー側で `No tracker found for session` として
  捨てられユーザーに届かない。

## 応急処置（配布前のユーザー向け）

「待っています」で止まった／`(No response from AI)` が出たら、同じセッションにもう一度
何か送れば応答が返る（孤児通知は 1 回目の空 result で消費される）。
