## 発見

- Agent には「アイドル判定」の手段が構造的に無い（`startAiSession()` がプロセスを spawn しないため `activeSessions`
  はセッション生存期間の指標にしかならない）ことを実装前に確認し、Server 主導スイープへの設計変更が正しかったと裏付け。
- Agent 共通層 `capability-rules.ts` の `aiToolToCapabilityProvider` 表は設計上 v1 で `claude: 'claude'` の
  1行を持つことが必須（将来 provider 追加はここに1行足すだけ、という抽象化の要）であり、これは「Claude 固有ロジック
  の漏れ」ではなく共通層とプロバイダ層の境界点そのものである（Server 側とは区別して整理）。
- `claude plugin update` の `updated` 判定は marketplace.json の大半が `source+sha` のみで `version` を持たないため、
  sha のみの更新は `present` 扱いになりやすい既知の限界（v1 として受容、E2E-6 で人間側検証待ち）。
