# #353: AI モデル選択リストの見直し（Claude Fable 5.1 対応）

## 要求

ユーザーから「Claude Fable 5.1 が出たのでモデル選択リストに追加してほしい。Fable 5 を残すか非推奨にするか提案してほしい。公式ラインナップが4モデルになったはず。料金テーブルも追加できないか。Flutter UI のモデル選択もお願い」との依頼。

## 調査（前提の検証、#345 の教訓）

依頼の前提3点をすべて実測で検証したところ、3点とも誤りだった：

1. 「Fable 5 を非推奨にするか判断してほしい」→ Anthropic 公式 deprecations ページで `claude-fable-5` は Active（retirement ≥2027-06-09）。削除・非推奨化の根拠なし。
2. 「公式ラインナップは4モデル」→ 実測では `claude-opus-4-8`（≥2027-05-28）を含め6モデル以上が Active。削除対象は1つも無い。
3. 「料金テーブルを追加」→ リポジトリ内に料金テーブル・コスト計算の消費者コードが1つも存在しない（`price`/`cost`/`perMTok` の実装ヒット0件）。追加は新規実装になり、`description` フィールドへの埋め込みで足りると判断。

さらに「Flutter UI」はこのリポジトリに一切存在しない（`.dart`/`pubspec.yaml` 0件）ことを確認。DevRelay 自身の UI は `apps/web`（Vite+React）のみで、Flutter は scaffold テンプレートの生成対象であって DevRelay 自身の UI ではない。ユーザーの承認ノートでも「Flutter側は対象外」と明示的に確認された。

Claude Fable 5.1 の3つの breaking change（forced tool use のエラー化、旧モデルの thinking block 非対応、過去ターン編集での thinking block 無効化）はいずれも DevRelay のコードに該当しないことも確認済み（`tool_choice`/`thinking`/`budget_tokens` の使用実績なし、messages 配列の手動編集なし）。

## 副次発見（本題より緊急度が高いリスク）

`AI_MODEL_CATALOG` の外側で、サーバー内製の要約/解析タスク（会話要約・ビルド要約・自然言語コマンド解析・Dev Report 生成・エージェント管理の画面解析/応答要約）が `claude-haiku-4-5-20251001` を **7 箇所に分散してハードコード**していた。うち全箇所が `temperature` を渡しており、`temperature`/`top_p`/`top_k` は Claude Opus 4.7 以降で 400 エラーになる仕様のため、将来このモデルを差し替える際の地雷になっていた。加えて `claude-haiku-4-5-20251001` の retirement（≥2026-10-15）はカタログ内で最も近い。
