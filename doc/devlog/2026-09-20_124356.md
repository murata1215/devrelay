# サイクル SDK-1: claude 実行ファイル検出器の 0.2 / 0.3 両対応化（コミット①②③）

## 背景

`doc/sdk-0.3-migration-findings.md`（サイクル SDK-0、commit `7a0913e`、origin/main 反映済み）で、
0.2.80 → 0.3.278 への移行で壊れる箇所は `getClaudeExecutableFallback()` の判定ロジック1箇所だけと
特定できた。0.3 系は同梱 `cli.js` が消滅しプラットフォーム別ネイティブバイナリ方式へ変わったため、
現行の「`cli.js` があるか」判定は 0.3 系では必ず「欠落」と誤判定し、全機で無条件にシステム
claude へフォールバックしてしまう。

findings §11 の不変条件「検出ロジックの書き換えを先に全機へ行き渡らせ、依存バンプは最後」に従い、
本サイクル（SDK-1）は検出器を 0.2 / 0.3 両対応にするところまでを行った。**依存バージョン自体を
0.3.x へ上げるコミット④は本サイクルに含まない。** `package.json` / `pnpm-lock.yaml` /
`node_modules` の変更はゼロ。

## コミット②: 検出器の 0.2 / 0.3 両対応化

### 設計

候補集合 = {0.2 系 `cli.js`} ∪ {0.3 系ネイティブバイナリ}。バージョン判定は一切しない。
どちらかが見つかれば `null` を返して SDK に委ね、どちらも無い時だけ `resolveSystemClaude()`
（#287 の安全網）。順序は `cli.js` を先に見る。0.2.80 上ではここで確定し、新規追加した
0.3 系の解決コードに一度も到達しない（＝「判定結果が完全に同一」を構造的に保証）。

0.3 系の解決は findings 訂正3 に従い解決済み `sdk.mjs` を起点にした `createRequire` を使用。
Agent 側モジュール起点だと pnpm では健全なインストールでも必ず `MODULE_NOT_FOUND`。

### 新規ファイル（4本、linux/macos byte-identical）

- `agents/{linux,macos}/src/services/sdk-executable-locator.ts` — 外部 import ゼロの純関数群
  （`preferMuslFromGlibc` / `sdkNativeBinarySpecifiers` / `runSdkExecutableProbe` /
  `decideSdkExecutable` / `buildSdkExecutableStatusLine` / `buildSdkExecutableTriedLine`）
- `agents/{linux,macos}/src/services/sdk-executable.ts` — I/O 薄皮
  （`probeSdkExecutable` / `getClaudeExecutableFallback` / `logClaudeExecutableStatus`）

### 既存ファイルの変更

`agents/{linux,macos}/src/services/ai-runner.ts` から `getClaudeExecutableFallback()` /
`logClaudeExecutableStatus()` の本体（linux 側は `createRequire` 直呼び出し含む約50行、
macos 側も同様）を削除し、`sdk-executable.js` からの re-export に置換。
不要になった `import { createRequire } from 'module'` も両ファイルから削除
（他に使用箇所が無いことを事前に `grep` で確認済み）。呼び出し元（`index.ts` /
`claude-login.ts`）は無変更。

### `agent.log` の1行

grep キー: `[SDK] claude-exec`。

```
🩺 [SDK] claude-exec sdk=<version|unknown> cc=<claudeCodeVersion|unknown> form=<clijs|native|none|unresolved> decision=<sdk-default|system-claude|none> platform=<platform>-<arch> preferMusl=<true|false> probe=<ok|legacy> path=<実際に使われる実行ファイル|->
```

`form=none` のときは追加で `tried=<specifier,specifier>` の診断行を1行併記する。

## 反映

`apps/server` 無変更のため **`pm2 restart devrelay-server` は不要**。DB マイグレーションも不要。

- コミット②の push 完了時刻: **2026-09-20T03:41:33Z（UTC）** ≒ 2026-09-20 12:41:33（JST）
- Auto Update の bake time は既定120分・sweep間隔は既定30分
  （`apps/server/src/services/auto-updater.ts` の `DEFAULT_BAKE_MIN`/`DEFAULT_SWEEP_MIN`）。
  **push + 120分 = 2026-09-20T05:41:33Z 以降**に bake time のゲートが外れ、以後の sweep
  （最大30分間隔）で各機の Auto Update が反映される。急ぐ機体は運用者が `u` を実行すれば
  bake time を待たずに反映できる（本ドキュメント §3 カナリア手順を参照）。
- コミット③（ドキュメントのみ）は commit + push 後、特に反映確認は不要
  （Agent の挙動には影響しない）。

反映後の確認は `doc/sdk-executable-runbook.md` §2「`agent.log` の1行の読み方」と
§3「カナリア手順」に記載の grep コマンドで行う。④（依存バンプ）は本サイクルには含まれておらず、
④に進む条件（3系統すべてで `form=clijs decision=sdk-default probe=ok` を確認）を満たしてから
次サイクルとして着手する。
