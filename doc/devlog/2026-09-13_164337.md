要求: hp630g9/fwjg2 の実機検証（claude 2.1.266）で Capability 配布（P1〜P1.2）が実質機能していないことが判明（`.claude/settings.json` の宣言で `installed 1` は報告されるが、実体は Agent 自身の作業ディレクトリに `scope: local` で install されており、対象プロジェクトの `claude plugin list` は `✘ failed to load`）。真因は (1) CLI 呼び出しに `cwd` を渡していなかったこと、(2) install scope を常に `--scope local` に固定していたこと。この 2 点の根治とあわせ、§8.2 の未実装項目（索引未知 ID への `marketplace update` 再試行、marketplace 未登録時の初回フォールバック）を実装した。スコープは `agents/linux` のみ。

実行: Step 0 で `ubuntu-prod/devrelay` の `claude` CLI を実測し、`plugin list --json` の主キーが `name` ではなく `id` であること（P1/P1.2 からの潜在バグ）、`enabled:true` だけでは scope/projectPath 不一致を見逃すこと、索引未知 ID のエラー文言（stdout, exit 1）、`marketplace list --json` の形状を確定した。テスト可能化のため `resolveSystemClaude()` を新規 `claude-path.ts` に移設し `ai-runner.ts` から再エクスポート（後方互換）、新規 `capabilities/claude-cli.ts` で `cwd` を型レベル必須にした spawn ヘルパを追加。`claude-plugin-rules.ts` に `resolveInstallScope`（宣言元 project/local から scope を解決、両方なら project 優先）、`evaluatePluginAtScope`/`isSatisfiedAtScope`（scope・projectPath cross-check、`unknownScopePolicy` 既定 accept で fail-open）、`parseMarketplaceListJson`/`evaluateMarketplaceList`（`unknown` は fail-open）、`isPluginNotInIndexError`（timeout kill・spawn失敗は false）を追加。`claude-plugin-adapter.ts` を `ClaudePluginDeps` 注入形に全面リファクタし `reconcileMachineWithDeps`/`reconcileProjectWithDeps` を新設: prelaunch の全 CLI 呼び出しは `cwd=projectPath`、machine は `cwd=getConfigDir()`（無ければ `os.homedir()`、`os.tmpdir()` は不使用）に固定。install scope は宣言元ファイル（project/local）に合わせ、present 判定は scope+projectPath 一致を要求し、install 後に同じ list で再検証してから `installed` に数える（不一致は `install-verify-failed`）。索引未知エラーは呼び出しごとのローカル変数で `marketplace update` を最大1回のみ実行し install を1回再試行。marketplace 未登録時は prelaunch から `marketplace add` を一切行わず、`capability-sync.ts` に新設した `CapabilityCtx.requestMachineReconcile?`（prelaunch のみ注入、machine 経路では undefined＝型で自己再帰を防止）を1回呼んで machine reconcile に委譲し `failed:[{id:'marketplace:<name>',reason:'marketplace-not-registered'}]` を積んで即 return。`capability-rules.ts` に純関数 `decidePrelaunchStatus()` を追加し、`capability-sync.ts` の prelaunch 送信 payload の `status` をハードコード `'done'` からこの導出結果（`skipped`/`error`/`done`）に置換（従来 install 失敗でも `done` を報告していた挙動の意図的な変更）。
