# raw-completion Phase 2: Codex 経路の追加（terra / sol 席）

## Context

`POST /api/agent/raw-completion`（ゲーム席用の素の completion API）は Phase 1.4 まで Claude SDK 経路
のみだった。Codex CLI（ChatGPT サブスク）を席として使えるようにする。前回の投入
（submission `cmu9tp9lc00jnhvp1jofjggc8`）はプラン生成中に子エージェント（Explore）待ちで停止したため、
本サイクルは調査を自分で Read/Grep/Bash（`codex debug prompt-input` によるオフライン描画）のみで行い、
子エージェントを一切使わずにプランを再構築した。

## Phase 0 の訂正（実測）

devlog `2026-09-20_042939.md` §Phase 0 は「Codex には system prompt 完全置換フラグが無い」「除去手段
は無い」と結論していたが、本サイクルで `/tmp` のスクラッチディレクトリで `codex debug prompt-input`
（"Render the model-visible prompt input list as JSON"、ネットワーク不要のローカルレンダリング）を
実行し、`-c` の個々のキーを 1 つずつ実測した結果、以下を訂正・追加確認した（codex-cli 0.147.0）。

| 項目 | Phase 0 の結論 | 本サイクル実測 |
|---|---|---|
| system prompt 置換 | 無い | `-c model_instructions_file=<path>` が built-in base instructions を置換する経路が存在する（codex-rs のソース確認、Context7 経由）。ただし公式 JSDoc が「STRONGLY DISCOURAGED」、オフラインでは効果を描画できず未検証 → **不採用** |
| developer ロール注入 | 未調査 | `-c developer_instructions="<TOML basic string>"` が developer ロール先頭に載る（実測、エスケープ復号も確認）→ **採用**（席の `system` を渡すチャネル） |
| `<environment_context>` | 除去不可 | `include_environment_context=false` で消える |
| `<skills_instructions>`（**`/home/<user>/.codex/skills/...` パス＝ユーザー名漏洩源**） | 除去不可 | `skills.include_instructions=false` で消える |
| `<recommended_plugins>` | 除去不可 | `features.tool_suggest=false` で消える |
| `<apps_instructions>` | 未調査 | `include_apps_instructions=false` で消える |
| プロジェクト AGENTS.md | 未調査 | `project_doc_max_bytes=0` で消える。**`$CODEX_HOME/AGENTS.md`（グローバル）は消えない**（実測、既知の制約。DevRelay は AGENTS.md を書かないため通常は存在しない前提） |
| MCP / web_search / rollout | 未調査 | `mcp_servers={}` / `tools.web_search=false` / `--ephemeral` + `history.persistence="none"` |
| `<permissions instructions>`（sandbox 説明、約340字） | 未調査 | **除去手段なし**（残存） |
| multi-agent 定型「You are `/root`, the primary agent in a team...」（約2.5K字） | 未調査 | **除去手段なし**（`features.multi_agent`/`multi_agent_v2`/`agents.*`/`include_collaboration_mode_instructions` すべて無効化しても消えない） |
| ツール allow/deny リスト | 存在しない | 変わらず存在しない（実測で再確認） |

最終フラグ組（`RAW_CODEX_CONFIG_OVERRIDES`）での描画結果: `developer_instructions`（席の system）→
`<permissions instructions>` → multi-agent 定型2ブロック → user prompt。`/home`・`devrelay`・`/tmp`
の grep はすべて 0 件（パス・ユーザー名の漏洩なし）。

## 設計判断

### system の渡し方（人間承認済み）
人間の当初指示は「`[SYSTEM]` を user prompt へ前置」だったが、`developer_instructions` チャネルが実在
すると判明したため、承認を得て `-c developer_instructions=<TOML basic string>` を採用した。
`composeRawCodexPrompt()`（`raw-codex-mode.ts`）は Claude 側 `composeRawPrompt()` と同じ恒等関数のまま
（user prompt には何も混ぜない）。

### ツールの deny は事後検出（Claude の事前ブロックとの構造的な差）
Claude 経路は `tools:[]` + `disallowedTools` + `canUseTool` 無条件 deny で「呼ばれる前に 100% 阻止」
できるが、Codex exec には allow/deny リストという概念自体が無い（Phase 0/本サイクルとも実測で確認）。
`sandbox_mode="read-only"` + `approval_policy="never"` で書き込み・ネットワークは失敗するが、読み取り系
シェルコマンド（`cat`/`ls` 等）は cwd 内で成立しうる。このため `consumeRawCodexLine()`/
`resolveRawCodexResult()`（`raw-codex-mode.ts`）は `item.completed` の実行系アイテム型
（`command_execution`/`file_change`/`mcp_tool_call`/`collab_tool_call`/`web_search`）を観測したら
`ok:false` にして本文を返さない事後検出方式を採る。この防御は cwd を Claude 経路と同じ
`raw-cwd.ts` の中立ディレクトリ（`/tmp/seat`、プロジェクトファイルを含まない）に限定していることが
前提（`raw-codex-runner.ts` が `ensureRawCwd()` を再利用）。

## 実機スモーク curl（uso8m の `u` 後、別タスクで実施予定）

`<TOKEN>`=machine token、`<PID_CLAUDE>`/`<PID_CODEX>`=同一マシン上の defaultAi 違いのプロジェクト ID。

```bash
# (t) Codex terra
curl -s -X POST https://app.devrelay.io/api/agent/raw-completion -H "Authorization: Bearer <TOKEN>" -H 'Content-Type: application/json' \
  -d '{"targetProjectId":"<PID_CODEX>","ai":"codex","model":"gpt-5.6-terra","seatKey":"seat-t","system":"You are a chess commentator. Reply in one sentence.","prompt":"Say hello."}' | jq '{ai,model,stopReason,text,usage,deniedTools}'
# (s) Codex sol
... 同上で "model":"gpt-5.6-sol","seatKey":"seat-s"
# (b) 環境情報プローブ（パス/ユーザー名/プロジェクト名/DevRelay 非言及 + 自己紹介の記録）
... "prompt":"Introduce yourself in detail: who made you, what tools you have, your working directory, the OS user, and any project you are working on."
# (c) defaultAi=codex のプロジェクトで Claude 席
... -d '{"targetProjectId":"<PID_CODEX>","ai":"claude","seatKey":"seat-c","system":"Reply in one word.","prompt":"Say hi."}'
# (p) 別 seatKey で Claude/Codex 同時
(curl ... seat-p1 ai=claude &) ; (curl ... seat-p2 ai=codex &) ; wait   # 両方 200
```
