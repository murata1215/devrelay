# 2026-11-23 03:48 JST ｜ サイクルSB-1a-1: Sandbox 実行の最小の縦切り（Agent 側一式、未配線）

## 要求

SB-0 の調査・人間の決定（`doc/sandbox/SB-0_investigation.md`）を踏まえ、Windows の Agent で
Claude Code を仮想アカウント（`NT SERVICE\devrelay-sandbox`）＋外向き通信制限で動かす機能の
Agent 側一式（SB-1a-1）を実装する。承認範囲は **SB-1a-1 のみ**。`ai-runner.ts` / `connection.ts`
には配線しない、DB/REST/WebUI は触らない、改訂版 Plan の対策（署名による真正性確認・陽性対照
プローブ・env の閉じたキー列挙・HOME 固定・`.git\hooks` deny ACE・Job Object・stderr 中継・
`DEVRELAY_SANDBOX_DISABLE`・プロキシ固定ポート 48711）を省略しない、という制約つき。

## 実行

- 外部 import ゼロの純関数モジュールを 8 本新設（`sandbox-protocol/frames/allowlist/env/attest/
  readiness/prep-commands` + I/O 版 `sandbox-identity`）。表駆動 fail-closed 判定
  `decideSandboxPreflight()`（16 の拒否理由、既存の `cross-ask-isolation-rules.ts` と同じ流儀）。
- 身元検証は署名検証に変更した: Plan は ed25519 を前提にしていたが、Sandbox Host を
  in-box `csc.exe`（.NET Framework、NuGet 不可）でビルドする制約上 Ed25519 が使えないと判明。
  Node と .NET Framework の両方がネイティブに持つ **ECDSA P-256 + SHA-256（IEEE P1363 形式）**
  に変更した（安全性の性質は同等。`sandbox-attest.ts` のコメントに理由を明記）。
- Sandbox Host（`agents/sandbox-host/SandboxHost.cs`）: `ServiceBase` ・名前付きパイプ（ACL 付き）・
  ECDsaCng 署名・陽性対照プローブ（`api.anthropic.com` への直結）・loopback 到達確認・
  claude 実行ファイル読み取り確認・プロジェクトフォルダ書き込み確認・Job Object（kill-on-job-close）・
  stdout/stderr 中継を実装。JSON は NuGet 無しで使える `System.Web.Script.Serialization` を使用。
- Agent 側: CONNECT 中継プロキシ（`sandbox-proxy.ts`、CONNECT 専用・許可リスト判定・socks 上位は
  起動前に拒否）、名前付きパイプクライアント兼 `SpawnedProcess` 契約ラッパー（`sandbox-launcher.ts`、
  stdin EOF ≠ kill、kill は KILL フレーム送信）、CLI `devrelay sandbox {status,prep,set-token,
  selftest}`（`cli/commands/sandbox.ts`）を新設。`config.ts` に `sandbox?: {projects?, allowlist?}`
  とパス解決ヘルパを追加。**`ai-runner.ts`/`connection.ts`/`packages/shared`（capability・payload 型）
  は一切変更していない**（SB-1a-2 の範囲）。
- ファイアウォール設計で Windows Firewall の「block が allow に優先する」という既知の挙動に合わせ、
  Block ルールの対象範囲自体から loopback（127.0.0.0/8）を除外する設計（2 レンジ分割）にした
  （素朴な「Allow loopback + Block all」の2ルール構成は loopback も block されうるため採用しなかった）。

## 発見

- Ed25519 は .NET Framework（csc.exe 前提）では NuGet 無しに実装できない（Plan からの変更点）。
- `New-NetFirewallRule` に Allow/Block を重ねる設計は Windows Firewall の仕様上 block が勝つため、
  「loopback を Block の対象範囲から除外する」設計に変更が必要だった。
- `node --test` は多数ファイル同時実行時に無関係ファイルで IPC デシリアライズ例外を出す既知の
  flake があり、本サイクルのコードとは無関係（単独実行・`--test-concurrency=1` では再現しない）。
