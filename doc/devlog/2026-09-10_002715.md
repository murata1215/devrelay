# スレッド管理 サイクル2（agent A1）: scope-aware な会話クリア

## 背景

サイクル1（server 側）で `Session` 行 = スレッド化が完了し、`agentScopeId` を採番できるようになった。
しかし agent 側 `handleConversationClear` は `agentScopeId` 未対応で `.devrelay/` 直下（既定スレッド）しか
クリアできないため、scoped スレッドでの `x` は server 側で暫定 fail-closed になっていた
（`command-handler.ts:786-800` の TODO）。本サイクルで agent 側を scope-aware にし、
server のガードを capability 判定に置き換える。

## 読み取り調査で確定した事実

- `scope-dir.ts` は linux/macos で byte-for-byte 同一（diff ゼロ）
- `conversation-store.ts` の linux/macos 差分は `getConversationContext()`（#372 進捗マーカー除去/plan選定）のみ。
  本サイクルが触る `archiveConversation()` は 3 OS 完全同一
- `session-store.ts` の `clear*()` 系はすでに全て `(projectPath, agentScopeId?)` 対応済み。
  未対応だったのは `archiveConversation()` のみ
- `conversation-store.ts:11-13` と `tests/conversation-store-scope.test.mjs:72-87` に
  「アーカイブは意図的にスコープ化しない」という既存の回帰テストがあり、spec §4 の要求
  （アーカイブ先もscope配下）と衝突するため、コメント・テストごと更新する対象と確定
- ディスパッチが `handleConversationClear(payload)` を await せず投げっぱなしのため、
  不正 scope 例外で unhandled rejection になりうる → try/catch を追加する対象と確定

## 実装方針（承認済みプラン要旨）

1. `packages/shared/src/types.ts`: `server:conversation:clear` payload に `agentScopeId?`、
   `AgentConnectPayload` に `capabilities?: AgentCapability[]` を追加
2. `agents/{linux,macos,windows}`: `archiveConversation()` の scope 化 + `handleConversationClear` の
   scope 対応・try/catch・capabilities 送信（macos/windows は個別編集、丸ごとコピー禁止）
3. `apps/server`: 新規 `thread-clear-guard.ts`（純関数）+ `agent-manager.ts` の capability 保持
   （メモリ Map のみ、DB化しない）+ `command-handler.ts` の TODO 解消
4. テスト: server 新規 + agent 3OS の conversation-store-scope 更新（アーカイブscope化+既定スレッド無傷+例外安全）
