# 2026-09-17 21:05 JST ｜ Uninstall コマンドの強化（Windows GUI版取り逃し穴の修正）

lfuser 機のチャットで `a` を送ると devin が消える（`1. Claude Code (default)` しか出ない）という報告を調査した。`a` は DB ではなく接続中 Agent へのライブ RPC（`agent-manager.ts:2246 getAiToolList()`）であり、`Machine` テーブルに `aiTools` 列は無い。Agent 側の `detectAndUpdateAiTools()` は追加専用で devin が自然消滅することはないため、設定破損ではないと判断した。

サーバーログ（`~/.pm2/logs/devrelay-server-out.log`）を確認すると、20:09:37 JST から `Closing stale WebSocket for cmu378r0608semst3wd819t6a` が34回、1回おきに `Soft-deleted 7 stale project(s)` が記録されていた。同一トークンを持つ Agent が2つ、交互に WebSocket を奪い合っていたことが確定した。マシン識別子は machineId ではなく token（`handleAgentConnect`:376）であり、後発が先発を `terminate()` する。

決定的だったのは、`agents/windows`（Electron GUI 版）と `agents/linux`（Windows で動く CLI 版）が同一の `%APPDATA%\devrelay\config.yaml` を読むという発見だった。1台の PC に両方インストールされていれば、同じトークンで2本接続してしまう。インストーラのトークン事前検証は COMPUTERNAME/USERNAME の一致しか見ないため、同一 PC 内の二重インストールを検出できない。

当初はインストーラに purge を組み込む案を立てたが、「アンインストールは危険」というユーザー判断を受けて方針転換した。調べると WebUI の Agents → 歯車 → Uninstall には既にコピー可能な一行コマンドが存在しており、新機能の追加ではなく既存コマンドの穴を塞ぐ作業だと判明した。

現行 Windows 用一行は `Name='node.exe'` のプロセスしか止めないため Electron GUI 版を取り逃す、タスクスケジューラ（Startup 登録失敗時のフォールバック）を消さない、OS タブの既定が常に Linux でユーザーが Windows マシンを開いても最初に Linux 用コマンドが出る、という3つの穴があった。

新規 `apps/web/src/lib/uninstall-command-rules.ts`（外部 import ゼロの純関数、machine-display-rules.ts と同じ流儀）に `buildUninstallCommand`/`buildFullUninstallCommand`/`resolveSettingsOs` を実装した。Windows の一行は exe 名を問わず `CommandLine -like '*devrelay*'` で対象を広げつつ、`irm | iex` で実行した PowerShell 自身を誤って kill しないよう `$PID` と `powershell.exe`/`pwsh.exe` を除外する自己防御を組み込んだ。加えてタスクスケジューラ削除を追加。Linux/macOS の一行は現行コマンドと完全一致するテストで非退行を固定し、変更していない。

GUI 版との共存問題を根治するため、新規 `scripts/uninstall-agent.ps1` を作成した。既定は削除対象の一覧表示のみ（ドライラン相当）で、確認プロンプトで y を入力するまで何も削除しない。プロセス停止（exe名不問、自己kill防止込み）→ 自動起動解除（Startup VBS / タスクスケジューラ / レジストリ Run キー）→ ログの `%TEMP%` への退避 → `%APPDATA%\devrelay` 一式削除 → `~/.claude/skills/devrelay-*` 削除 → GUI 版（NSIS、appId=io.devrelay.agent）の検出・確認の上でのサイレントアンインストール → 他ユーザープロファイルや WSL の残留を報告のみ（削除しない）、という順で実装した。WebUI には Windows のときだけ「Full uninstall」として2本目のコマンドで表示する。`MachinesPage.tsx` の `handleOpenSettings` も修正し、モーダルを開いたときの OS タブ既定値を `Machine.managementInfo.os` から解決するようにした（従来は常に Linux 固定だった）。

push が反映される前に今日の lfuser 機を直接直せるよう、同内容を `.devrelay-output/dr-agent-uninstall.ps1` にもコピーして出力した。

検証: `apps/web` の `node --test` が新規14件を含め512 pass / 0 fail、`pnpm build` は6 workspace green、`grep -c 'require(' apps/web/dist/assets/index-*.js` は0（#310 の再発防止ゲート）、`git status --short -- agents/ apps/server/ packages/ prisma/` は空（スコープ逸脱なし）。`scripts/uninstall-agent.ps1` と `.devrelay-output/dr-agent-uninstall.ps1` は diff で完全一致。このサーバーには pwsh が無いため PowerShell の実行検証はできておらず、静的レビュー（kill 経路への `$PID` 除外の網羅、`Remove-Item` 前の `Set-Location`、`exit` を使っていないこと、トークンを表示しないこと）で代替した。実機 E2E は人間側で lfuser 機を使って実施する必要がある。

申し送り: (1) 別 PC に同じトークンの Agent が生きている場合はアンインストールでは直らない。WebUI でマシンを削除してトークンを無効化（`deleted_<ts>_<旧token>` にリネーム、`api.ts:203-231`）し、新トークンで入れ直す必要がある。(2) サーバー側の二重接続検知（`agent-manager.ts:428-433` の差し替え回数がしきい値超過でチャット通知）は未実装。今回サーバーログを読むまで誰も二重接続に気付けなかったため、再発防止として別サイクルでの実施が望ましい。(3) `install-agent.ps1` のトークン事前検証は COMPUTERNAME/USERNAME 一致のみで、同一 PC 内の二重インストールを検出できない穴は未対処。(4) lfuser 機は現在 `local=f6db459` で、先日の Devin ターン固まり修正（`03a0242`/`2702cfe`）を含んでいない。再インストールで最新 main になるため、そのE2E確認もあわせて実施できる。
