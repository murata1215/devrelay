## 変更1: model 判定ロジック（agents/linux + agents/macos、byte-identical）

`agents/{linux,macos}/src/services/raw-completion-mode.ts` に純関数 `resolveRawUsedModel()` を
新設。優先順位:

1. **テキストを生成した最後の assistant メッセージの `message.model`**（`"<synthetic>"` 等の無効値は除外）
2. リクエスト指定 `model` と一致する `modelUsage` エントリ（完全一致 → 前方一致の順。例: 指定
   `claude-opus-5` に対し `claude-opus-5-20260301` を許容）
3. `modelUsage` のうち `outputTokens` が最大のエントリ（最終手段。「出力トークン最大」を第一候補に
   しない理由: 応答が数トークンのとき Haiku 内部呼び出しの方が出力が多くなり再発するため）
4. 上記いずれも解決できなければ `undefined`

`agents/{linux,macos}/src/services/ai-runner.ts`（`sendPromptToAiSdk`）に `lastTextAssistantModel`
変数を追加し、assistant テキストブロック処理時に記録。result ハンドラの `usageData.model` は
`options.rawMode` のときだけ `resolveRawUsedModel()` を使い、非 rawMode（plan/exec 既存経路）は
従来どおり `modelUsage` の先頭キーのまま変更していない（既存経路への影響ゼロ）。

サーバー側 `apps/server/src/services/raw-completion-response.ts` の `resolveRawModel()` も同じ
優先順位（`usageData.model` → requestedModel 一致の modelUsage キー → outputTokens 最大 →
requestedModel → undefined）に整合させた。新 Agent が正しい `usageData.model` を送ればそのまま
通り、旧 Agent や `model` 欠落時の保険として機能する。

Haiku 分の usage（F4 で確認した「usage 4キーには元から含まれない」件）について: `usageData.usage`
（HTTP `usage` フィールドの元）は SDK 仕様上 main agent loop のみを集計するため、そもそも本体分
以外は混入しない。`usageData.modelUsage` には別キー（`costUSD` 付き）として記録されており、
コスト分析が必要な場合はそちらから分離可能。本サイクルの env 追加（下記）によりこの Haiku
呼び出し自体が発生しなくなるため、以後は分離の必要すら無くなる。

## 変更2: raw 経路の cwd を中立な固定ディレクトリに（agents/linux + agents/macos、byte-identical）

新規 `agents/{linux,macos}/src/services/raw-cwd.ts`:

- **`/tmp/seat` 固定**（POSIX）を採用。候補比較:
  - `$XDG_RUNTIME_DIR/seat`: 不採用（この機体は crontab `@reboot` nohup 起動で
    `XDG_RUNTIME_DIR` が未設定。設定されていてもパスに UID が入る）
  - `os.tmpdir()/seat`: 不採用（`TMPDIR` 環境変数次第でユーザー名入りパスに化けうる）
  - `~/.devrelay/raw-cwd`: 不採用（devrelay・ユーザー名の両方を含む、人間指示の禁止条件に抵触）
  - `/tmp/seat`: 採用。パスに devrelay・ユーザー名・ホスト名を一切含まず、全 POSIX 機に存在
- 安全策: `mkdir(mode 0o700)` 後に `lstat` で「ディレクトリである・symlink でない・所有 uid が
  自プロセスの uid と一致する」を検証。不合格ならプロセス寿命中 1 回だけ `mkdtemp` にフォールバック
  （結果をモジュール内にキャッシュし、呼び出しごとの増殖を防ぐ）。
- Windows（win32）は `os.tmpdir()/seat` にフォールバック（Windows Electron agent は raw-completion
  対象外＝D4 のため型上の完全性のためだけに用意。`path.win32.join` を明示使用 — 実装中に
  `path.join`（ランタイム OS 依存のセパレータ選択）を使うと、POSIX ホスト上でこの関数を単体
  テストした際に Windows 形パスを期待するテストが落ちるバグを検出し修正した）。

`agents/{linux,macos}/src/services/connection.ts` の `handleRawPrompt()` で、`sendPromptToAi()`
の第3引数（cwd）を `payload.projectPath` から `ensureRawCwd()` に差し替え。`payload.projectPath`
は raw 経路内で未使用のまま残し、既存経路（plan/exec）の `cwd: projectPath` 決定ロジックには
一切触れていない。

`raw-completion-mode.ts` の `buildRawSdkOverrides()` に `persistSession: false` を追加（F9）。
トランスクリプト書き込み自体を止め、`~/.claude/projects/-tmp-seat/` のスラッグ生成をゼロにする。

`RAW_ENV_OVERRIDES` に2キー追加（いずれも raw 経路の env にのみマージ、既存経路には無関係）:

```
CLAUDE_CODE_DISABLE_TERMINAL_TITLE: '1'    // Haiku タイトル生成を止める（F3、実測で modelUsage が1キーに）
CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS: '1'  // git status/commit 指示の注入を止める（F8、現状未注入だが保険）
```

**環境アタッチメント（F6）と userEmail（F5）は SDK 側で止める手段が無いため実装していない**
（`--bare` は F7 により OAuth 認証と両立不可のため不採用）。
