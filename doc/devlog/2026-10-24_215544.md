# 2026-10-24 21:55 JST ｜ サイクル: u の busy 自家中毒修正と u force 一発化

## 要求
WebUI から `u` を送っても自動更新が永久に保留され続ける（WebUI のコマンド永続化と busy 判定が
干渉し自家中毒を起こしている疑い）。合わせて、保留理由の誤表示（数えていない値を「1件」と表示）、
Agent 再接続時の実行中ターン台帳の掃除漏れ、`u force` が実質機能しない問題も調査・修正する
依頼。プランモードで read-only 調査→Plan 提出→承認を経て実装した。

## 実行
真因は recent activity 判定（直近10分の Message 有無）が role を問わず見ていたため、`u` 自身の
入力/応答行を踏んで busy と誤判定し続けていたこと。`buildRecentAiActivityWhere()` で `role='ai'`
限定に修正。session running 判定も `isSessionRunning()`（tracker 有無）から `getProgressTrackerAgeMs()`
+ `RUNNING_FRESHNESS_MS`（鮮度ベース）に変更し、tracker 回収漏れからの自己回復力を上げた。
`extractBusyCount()`（数字無し理由を一律1件に丸める）を削除し `BusyState{kind,count:number|null}`
を新設、理由別 i18n キー3件を ja/en 追加。`handleAgentConnect()` にも `inFlightTurns.clearMachine()`
を追加し、再接続順序に依らず台帳を掃除。`decideUpdateFlow()` を新設し `u force` 指定時は
バージョン確認後 2 段階確認を待たず即実行するようにした。手動 `u`・restart API の hold 時に
busyReason を 1 行ログ出力。

## 検証
`pnpm build`（6 workspace）green。`node --test`: server 1371/1371（新規28）・shared 104/104・
web 888/888（0行変更）全て green。`agents/*`・`apps/web`・`packages/shared` のコードは
i18n キー追加のみでロジック 0 行変更のため各機 `u` 不要。DB マイグレーション無し。
