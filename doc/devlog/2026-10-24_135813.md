# 2026-10-24 13:58 JST ｜ サイクル: 読取PATのサーバー配布

## 要求
前サイクル（`fa62645`）で会社 private リポジトリ clone 対応を入れたが、PAT は社員への手渡し・
失効時は全台 `--repo-auth-only` が必要という運用負荷が残っていた。これを「サーバー `.env` に
1 か所設定 → 認証済み Agent に自動配布」に変える依頼。人間承認で2点追加: (1) macOS の `u` を
Linux（`fa62645`）相当の exit code チェック・pre-flight 認証チェックに揃える、(2) `Machine.token`
平文保存による「DB 侵害＝PAT 配布権奪取」リスクを明示的に許容して進める。

## 実行
配布経路は2つ: インストール時は新規 `POST /api/agent/repo-auth`（マシントークン Bearer 認証・
HTTPS 限定・レート制限）、`u` 実行前は要求ドリブンの WS 往復（`agent:repo:auth:request` →
`server:repo:auth`、5秒タイムアウト）。origin が public 既定 URL の機体は一切問い合わせない
設計にし、個人 devrelay.io を含む既存環境を無変更に保った。サーバーは生 PAT ではなく
`Authorization: Basic <base64>` を返す。`agents/linux`/`agents/macos` の `repo-auth-rules.ts` に
純関数4つ（`.git/config` 読み書き・URL 判定）を byte-for-byte 同一で追加し、`connection.ts` に
`refreshRepoAuthFromServer()` を配線。macOS の `u` も Linux と同じ `runAndLogChecked` + pre-flight
`git ls-remote` チェックに揃えた。インストーラ（sh/ps1）は手入力 PAT 未指定時にサーバーへ
問い合わせ、取得できなければ従来の対話入力にフォールバックする。

## 発見
- `/api/public/validate-token` は認証不要・レート制限なし・無効トークンでも 200 を返す設計で、
  秘密配布には構造的に不適だった（新規 `/api/agent/repo-auth` に分離した理由）
- `server:agent:update`（既存、payload 空）に PAT を同梱する案は「PAT 不要な機体にも毎回送る」
  ことになり露出面が広がるため却下。要求ドリブン WS にした
- 作業ツリーに他セッションの未コミット WIP（x220 crontab 修正・systemd 修正・projectName 表示
  バグ修正等）が混在していたため、`connection.ts`/`agent-manager.ts`/`changelog.md` の3ファイルは
  コミット前に一時的に自分の差分だけへ戻し、コミット後に他セッションの差分を作業ツリーへ
  復元した（他セッションの WIP は未コミットのまま維持、自分のコミットには混入していない）
