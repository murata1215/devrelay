## 要求

P3-A で実装した `devin:skill` adapter は「Devin というツール名」に紐づいた設計ミスだった。実際に配布しているのは Claude plugin の `skills/<name>/` を **Agent Skills 標準**（`~/.agents/skills/<name>/SKILL.md`）に置くことで、この置き場は Devin CLI と Codex が両方読む。プラン `/home/devrelay/.claude/plans/rippling-humming-tide.md`（事前承認済み、6項目の拘束的補足あり）に基づき、以下を実施する。

1. **昇格**: `provider='devin'/kind='skill'` → `provider='agent-skills'/kind='standard'`（registry key `agent-skills:standard`）。ツール別 opt-in（`providers.devin` チェックボックス）を廃止。
2. **移行**: P3-A が `%APPDATA%\devin\skills` に作った managed 状態を、新配布先の成功を確認してから安全に回収する（失敗時は legacy を last-known-good として保全するゲート必須）。
3. **磨き**: P3-A E2E で判明した4点（item id 二重サフィックス、Claude adapter の未検証 installed 報告、breakdown に present/removed 欠如、devlog ファイル名の手打ち規約違反）を解消。

承認ノートの拘束的補足: (1) プラン§10 O1〜O6 は提案どおり承認、(2) 診断文字列は Devin=実ランタイム検出／Codex=DevRelay `aiTools` config 有無、と根拠を書き分ける、(3) 完了報告のテスト件数は実測値のみ（推測禁止）、(4) `removed` 配列の `legacy:` prefix は web 詳細表示で可視のまま、(5) P3-A 承認ノート（`doc/p3a_devin_skill_adapter_approval_note.md`）の確認済み事項（移行ゲート・unmanaged 不干渉・fetch失敗時 last-known-good）は必須テストとして維持、(6) devlog 採番は `TZ=Asia/Tokyo date` の実出力を使い、P3-A の devlog も `git mv` でリネームし INDEX.md を修正する。
