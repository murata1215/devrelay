# #340 `login` 通知文言・ヘルプの追従修正

## 要求
ユーザーから「サーバー再起動していない。macでuしたけど、これは想定通り？ログイン用URL出てきて
ほしいけど。」（スクショは実際には `ubuntu-prod/pixblog`）→ 続けて「Use --update-env … restart
したよ … 何もしなくていい？」という報告・質問。#339（`login` コマンド本体）実装直後のデプロイ
検証で発生した2つの疑問（stale サーバーの見分け方、PM2 の `--update-env` 通知の要否）を解消し、
併せて調査中に見つかった文言の追従漏れ（#339 実装時点で `login` が使えるようになったのに通知・
ヘルプが「（実装後）」のまま）を修正する。

## 実行
1. **stale 判定**: `pm2 describe devrelay-server` の `created at` と `out.log` の
   `🏗️  build:` 行（#319 の再発防止ガード）を比較。ユーザーが最初にスクショを見た時点では
   `pm2` の起動時刻が #339 のビルドより前で、真の意味で「まだ再起動していない」状態と確定
   （コード自体にバグはなかった）。
2. **PM2 `--update-env` の要否確認**: `apps/server/src/index.ts:1` が `import 'dotenv/config'`
   であることを確認 → 起動のたびに `.env` をディスクから読み直すため PM2 の env スナップショット
   に依存しておらず、かつ #339 は環境変数を1つも追加していないため対応不要と判定。
3. **`claudeAuthOk` 巻き戻りの解析**: DB を再確認したところ pixblog の `claudeAuthOk` が `t` に
   戻っていた。`claude-auth-precedence.ts` の `decideClaudeAuthUpdate()` と Agent 側
   `connection.ts:1643` の `lastReportedClaudeAuthOk = null`（再接続時リセット）を突き合わせ、
   「stale サーバー上で BUG A（poll による上書き）が最後に発生 → 再起動時の再接続で全 Agent が
   再報告 → 新ロジックが `previousOk=true` を正しく維持」という一連の流れとして説明できることを
   確認（新しい runtime 401 が発生すれば以降は正しく `false` を維持する設計）。
4. **文言の追従漏れ修正**（テキストのみ、ロジック変更ゼロ）:
   - `packages/shared/src/i18n.ts` の `claudeAuth.expired`/`claudeAuth.runtimeExpiredHint`
     から「（実装後）」/`(once implemented)` を削除し、WebUI から `login` で再ログインできる
     旨に更新（ja/en）。
   - `apps/server/src/services/command-parser.ts` の `getHelpText()` に
     「Claude 再ログイン（WebUI のみ）」セクション（`login`/`login <code>`）を ja/en 両方に追加。
5. `pnpm build`（6 workspace）green を確認。

## 検証
- `pnpm build` 6 workspace すべて green。
- `grep -c 'require(' apps/web/dist/assets/index-*.js` = 0（web は今回無変更のため確認のみ）。
- `packages/shared/dist/i18n.js` に新しい `claudeAuth.expired`/`runtimeExpiredHint` 文言が
  反映されていることを確認（「実装後」の残存は無関係な JSDoc コメント1件のみと確認）。
- `apps/server/dist/services/command-parser.js` に ja/en 双方の新セクションが反映されている
  ことを確認。
- Agent 側 (`agents/{linux,macos}/src/services/ai-runner.ts`) は `tChat(lang,
  'claudeAuth.runtimeExpiredHint')` を呼ぶのみで文言自体は `packages/shared` 側の変更が
  ワークスペースリンク経由で反映されるため、Agent 側コード自体の変更はなし。

## 発見
- 「サーバー再起動していない」問題は真にユーザー環境側の stale プロセスであり、#319 で仕込んだ
  `🏗️  build:` ログが今回も一発で切り分けに使えた（3回目の類似事例だが毎回このガードで即座に
  判定できている）。
- PM2 の `--update-env` 通知は DevRelay では `dotenv/config` により実質無関係だが、これは
  「気づかれにくい安全な既定動作」であり、将来 `.env` に新規変数を追加する際は明示的に
  `pm2 restart devrelay-server --update-env` を使う必要がある旨をユーザーに案内する価値がある
  （コード変更は不要、運用知識として `CLAUDE.md`/`MEMORY.md` 側で明文化する余地は今後の検討）。
- `claudeAuthOk` の巻き戻りは #339 のバグではなく、#339 適用前の stale サーバーが起こした
  BUG A の最後の発現 + Agent 再接続時の意図的なリセット（`lastReportedClaudeAuthOk = null`）
  の組み合わせで完全に説明がつく既知動作であり、修正の必要はないと判断した。
