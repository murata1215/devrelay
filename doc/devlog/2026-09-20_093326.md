## Commit A — auto-memory 遮断（raw 経路のみ）commit `fc5fb57`

## Commit B — SDK 更新: 停止条件4により中止

### 試行内容

`package.json` 3箇所（root devDependencies / agents/linux / agents/macos dependencies）を
`@anthropic-ai/claude-agent-sdk` `0.3.278`（完全固定）に変更し `pnpm install` を実行した。

インストール自体は成功（`apps/server` の `@anthropic-ai/sdk@^0.78.0` importer edge は
`0.78.0` のまま無変更で floor 衝突なし、`agents/linux` に peer 警告
`unmet peer @anthropic-ai/sdk@>=0.93.0: found 0.78.0` が出たが **error ではなく warning**
だったため、プラン記載の待避策（agents 側への peer dep 追加）は不要と判断）。

### 発見した破壊的変更 — 停止条件4「cli.js が sdk.mjs の兄弟でなくなった」が確定発火

`0.3.278` の `@anthropic-ai/claude-agent-sdk` パッケージの中身を実際に展開して確認したところ、
**`cli.js` というファイルが一切存在しない**ことが判明した。

```
$ ls -la node_modules/.pnpm/@anthropic-ai+claude-agent-sdk@0.3.278*/node_modules/@anthropic-ai/claude-agent-sdk
LICENSE.md  README.md  agentSdkTypes.d.ts  bridge.d.ts  bridge.mjs  browser-sdk.d.ts
browser-sdk.js  extractFromBunfs.d.ts  extractFromBunfs.js  manifest.json
manifest.zst.json  node_modules  package.json  sdk-tools.d.ts  sdk.d.ts  sdk.mjs
```

`package.json` の `optionalDependencies` に、プラットフォームごとの新規パッケージ
（`@anthropic-ai/claude-agent-sdk-linux-x64` 等、8プラットフォーム分）が追加されており、
実行バイナリ自体はこちらに移動していた。`manifest.json` によると各プラットフォームの
`claude` / `claude.exe` バイナリは **217MB〜237MB**（linux-x64 は 234,119,480 bytes）——
Phase 1.3 計画時点の見積り「1機あたり約58MBの新SDKダウンロード」を大きく超える。

同梱の `extractFromBunfs.js`（新規ファイル）のヘッダコメントに設計思想が明記されている:

```js
// Extracts a file from Bun's $bunfs virtual filesystem to a real temp directory
// so it can be spawned as a subprocess (child processes cannot access $bunfs).
```

つまり 0.3.x 系では Claude Code 本体が **Bun でコンパイルされた単一バイナリ**になり、
SDK パッケージにはその抽出ロジック（`~/`配下ではなく `{tmpdir()}/claude-{uid}` へ、
所有権検証付きで展開）だけが同梱される形に変わっている。JS の `cli.js` を `node` の
子プロセスとして spawn する旧来のモデルとは根本的に別のアーキテクチャ。

### 既存コードへの影響（実測）

`agents/{linux,macos}/src/services/ai-runner.ts` の `getClaudeExecutableFallback()` と
`logClaudeExecutableStatus()` は両方とも

```ts
const bundledCli = path.join(path.dirname(sdkEntry), 'cli.js');
if (fs.existsSync(bundledCli)) { ... }
```

という判定のみを行っている。0.3.278 ではこの `cli.js` が恒久的に存在しないため
`fs.existsSync` は**常に `false`**を返し、`getClaudeExecutableFallback()` は
**すべての呼び出しで**システム `claude` へのフォールバックを試みることになる
（システム claude が無い環境では「bundled cli.js MISSING and no system claude found —
AI commands will fail」で全 AI コマンドが恒久的に失敗する）。プランの停止条件4が
想定していた「同梱バイナリ検出ロジックが誤報し全経路がシステム claude に逸れる」が
そのまま該当する。

これは型のリネームや import 修正で吸収できる範囲を超えており（停止条件6「型 shape 変更で
`canUseTool` のロジック修正が必要」とは別軸だが同じ「ロジック修正が要る」に相当）、
本サイクルのスコープ外と判断し **Commit B を中止**した。

## 次サイクルへの申し送り

1. **`claude-fable-5-1` 修正（(e)）は本サイクルでは未解消。** SDK を 0.3.x 系へ上げるには
   `getClaudeExecutableFallback()` / `logClaudeExecutableStatus()` を新アーキテクチャ
   （`extractFromBunfs` 経由のプラットフォームバイナリ展開）に対応させる設計が必要。
   選択肢の見立て（次サイクルで検証すること）:
   - a) `pathToClaudeCodeExecutable` を一切指定せず SDK 既定の解決に委ねる
     （0.3.x の `sdk.mjs` 自身が `extractFromBunfs` 経由で解決するなら、フォールバック機構
     そのものが不要になる可能性がある。ただし「同梱バイナリが不完全インストールで欠落」時の
     診断ログ（#287 の教訓）が失われるため、検出方法を作り直す必要がある）
   - b) `manifest.json` の `platforms.<platform>.binary` から抽出先を自前解決し、
     `extractFromBunfs.js` の `./extract` export を使って同等のフォールバック検出を再実装する
   - c) プラットフォーム別 optional package（`@anthropic-ai/claude-agent-sdk-linux-x64` 等）が
     実際にインストールされているかを `require.resolve` で確認する方式に切り替える
   いずれも実装前に 0.3.x 系での実際の spawn 挙動（`pathToClaudeCodeExecutable` 未指定時に
   `sdk.mjs` が何を spawn するか）を実測してから設計すること。
2. **auto-memory 遮断（Commit A）は 0.2.77 のまま出荷済み。** SDK 0.3.x 系でも
   `CLAUDE_CODE_DISABLE_AUTO_MEMORY` env と `settings.autoMemoryEnabled` の対応関係が
   同じか、次の SDK 更新サイクルで cli.js 相当のバイナリを実際に展開してから
   ゲート関数の実測を再度行うこと（プランの停止条件3に相当。新バイナリは strings 等での
   grep が必要になる可能性が高い＝旧来の `grep` ベースの契約チェックスクリプトが使えない）。
3. バージョン分裂状態（ルート/agents とも 0.2.77 のまま、Commit B は完全に未適用）を維持。
   分裂出荷（プラン停止条件11）は発生していない — 単に SDK 更新自体を全面的に見送った。
