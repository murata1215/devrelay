# 2026-09-25 12:35 JST ｜ Claude Opus 5.5 対応（カタログ追加 + SDK バンプ + raw-completion 前方一致修正）

## 背景

ユーザーから WebUI 設定ページのモデル選択ドロップダウン画像を添えて「opus5.5 がでたみたい。
対応できる？」という依頼。公式ドキュメント（`platform.claude.com/docs/en/about-claude/models/overview.md`）
を WebFetch で実測し、Claude Opus 5.5（`claude-opus-5-5`）の実在を確認した。

## 調査で確定した事実

- **Claude Opus 5.5**: `claude-opus-5-5`、$4/input MTok・$20/output MTok（Opus 5 の $5/$25 より安い）、
  文脈1M/出力128K、adaptive thinking 常時オン、既定 effort=`medium`（他は `high`）、retirement
  2027-09-22 以降。公式は「ほとんどのワークロードはまず Opus 5.5 から」と推奨し、Fable 5/Opus 5/
  Opus 4.8 は legacy 扱いに移った（が Active＝利用可能のまま）
- 移行ガイドの breaking changes（`tool_choice` 強制・`thinking`/`budget_tokens` 拒否・prefill 廃止）は
  #353（Fable 5.1）と同様、DevRelay に該当コード0件
- **カタログ追加だけでは動かない**ことを実機で確認: 現行 SDK `0.3.278`（同梱 Claude Code 2.1.278）で
  `query({model:'claude-opus-5-5'})` を実行すると
  `API Error: 400 Claude Code 2.1.278 does not support this model; version 2.1.280 or newer is required`
  で明示的に拒否される。`rules/project.md` の「フル ID は CLI 更新不要で使える」という設計判断は
  #353 に続き**2度目**破れた
- `@anthropic-ai/claude-agent-sdk` の最新版 `0.3.282`（`claudeCodeVersion: "2.1.282"`、npm registry 実測）
  が要件を満たす。CC 2.1.280 の公開日は 2026-09-22＝Opus 5.5 launch 日と一致

  `claude-opus-5-5` を追加。**既存エントリの削除は0件**（#353 と同じ判断）。カタログ先頭 JSDoc に
  「フル ID でも CLI 更新不要」という前提の反証（#353 + 本サイクルで2度破れた事実）と、新モデル追加時に
  実機 `query()` で確認する手順を追記
- `packages/shared/tests/model-catalog.test.mjs`: `claude-opus-5-5` の存在アサート追加、
  `expectedRetained` を9→10件に拡張
- `README.md` / `rules/project.md`: モデル一覧を更新。`rules/project.md:536` の設計判断に訂正を追記
  （「フル ID は CLI 更新不要」は普遍的でない、実測して確認せよという注意）、新規 bullet で本サイクルの
  詳細を記録

### ② SDK バンプ 0.3.278 → 0.3.282
- `package.json`（root/`agents/linux`/`agents/macos` の3箇所）をキャレット無し完全固定で更新
- `pnpm install` で lockfile 更新。8プラットフォームの optionalDependencies が全て `0.3.282` に
  揃い、`0.3.278` の残骸が0件であることを確認。SDK 実体（`sdk.mjs`、1,135,207 bytes）が
  `readlink -f` で解決できることも確認（停止条件に該当せず）
- `agents/{linux,macos}/tests/sdk-version.test.mjs`: `MIN_CLAUDE_CODE_VERSION` を `2.1.251`→`2.1.280`
  に引き上げ（コメントの根拠も更新）。linux/macos は byte-identical を維持
- **ソース変更は発生せず**（SDK-1/SDK-2 と同じ設計がバンプを吸収）

### ③ raw-completion 前方一致の曖昧さ修正
`findModelUsageKeyMatchingRequest()`（server: `raw-completion-response.ts`）/
`resolveRawUsedModel()` 内の同名関数（agents/linux・macos: `raw-completion-mode.ts`）は
「完全一致→前方一致（複数なら最短キー）」でレスポンスの `model` を解決する。`claude-opus-5-5` の
登場により、`claude-opus-5` を要求したのに `modelUsage` に `claude-opus-5-5` と
`claude-opus-5-20260301`（本来の対象）の両方がある場合、修正前は最短キー優先ロジックが
**誤って `claude-opus-5-5`（別モデル）を選んでしまう**ことが判明（実害は表示のみ、優先順位1の
`usageData.model`/`lastAssistantModel` が通常勝つため発生頻度は低いが、Opus 5.5 登場で初めて
顕在化する曖昧さ）。

前方一致を「残り部分が `-YYYYMMDD`（8桁の日付スナップショット接尾辞）の場合のみ」に限定する
`isDateSnapshotSuffix()` を新設して修正。server・agents/linux・agents/macos の3箇所に同一ロジックを
適用（linux↔macos は byte-identical 維持）。回帰テストを各3ファイルに1ケースずつ追加
（`claude-opus-5-5` と `claude-opus-5-20260301` が modelUsage に共存する場合に後者を正しく選ぶこと）。
