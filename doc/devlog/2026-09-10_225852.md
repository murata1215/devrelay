# server 小修正: スレッド一覧の orderBy 欠落 + 削除済み除外（Lite L3 申し送り）

日時: 2026-09-10 22:58 (JST)
プラン: `~/.claude/plans/foamy-questing-fiddle.md`（read-only 調査プラン `~/.claude/plans/virtual-frolicking-candle.md` の実装サイクル）
スコープ: `apps/server` のみ。`apps/web` / `agents` / `packages` / `prisma/schema.prisma` は無変更、DB マイグレーション不要。

## 背景

Lite シェル L3 の `/lite` スレッド一覧が「(無題)・既定・5か月前」のような古いゴミしか出ない不具合。

## 発見

- **`orderBy` 欠落 + `take: 500` が横断モードでのみ顕在化**: `GET /api/threads`
  （`apps/server/src/routes/api.ts`）の `prisma.session.findMany` に `orderBy` が無かった。
  PostgreSQL は `ORDER BY` 無しでは順序を一切保証しない（実測では物理順＝最古から）。
  その状態で `take: 500` すると「新しい順の先頭 500 件」ではなく「任意の 500 件」が返り、
  JS 側の `sortThreadsDesc` はその 500 件の中でしか並べ替えられない。
  プロジェクト単位モード（`projectId` 指定）は母数が小さく 500 に収まるため実害が出ず、
  **横断モード（`projectId` 省略、Lite シェルが使う経路）でのみ**症状が表面化していた。
- **`lastActiveAt` 3126 件を人間側 psql で backfill 済み**（NULL 0 件）。本サイクル開始前に完了。
- 一時セッション（`teamexec_`/`crossquery_`/`askdesc_`）の除外が **LIMIT の後**の JS フィルタにあり、
  「除外された件数だけ一覧が短くなる」欠落バグの構造だった。
- ソフトデリート済み（`Project.deletedAt`/`Machine.deletedAt` 非 null）配下のスレッドを除外する条件が
  where に無かった。

## 変更内容

1. `apps/server/src/services/thread-scope.ts`
   - `EPHEMERAL_SESSION_ID_PREFIXES` に `askdesc_` を追加
     （`POST /api/projects/:id/description` が作る「user メッセージ無し・assistant 1 件のタイトル無し
     スレッド」が症状の一因だったため。`isEphemeralSessionId` の呼び出し元は
     `api.ts` の一覧 where（後述）と `session-manager.ts` の `touchSessionActivity` の 2 箇所のみで、
     後者は askdesc_ の id が構造上到達しないため影響ゼロと確認済み）。
   - `buildEphemeralSessionIdExclusion()` を新規追加。プレフィックス一覧を Prisma の `where` に
     スプレッドできる `NOT: { OR: [{ id: { startsWith } }, ...] }` 形へ変換する純関数。
     外部 import ゼロの規約は維持（`Prisma.SessionWhereInput` は import せず構造的に代入可能な
     最小型を自前宣言）。
2. `apps/server/src/services/session-manager.ts`
   - `createSession()` の `prisma.session.create` に `lastActiveAt: new Date()` を追加。
     `startedAt`（DB の `CURRENT_TIMESTAMP` 由来）とは別クロックになるが、`lastActiveAt` は
     ソートキーと表示にしか使わず両者を比較する箇所が無いため影響しない
     （`lastActiveAt >= startedAt` は不変条件にしない、とコメントで明記）。
3. `apps/server/src/routes/document-api.ts` / `apps/server/src/services/command-handler.ts` /
   `apps/server/src/routes/api.ts` — 一時セッションを直接 `prisma.session.create` する 5 箇所
   （crossquery_ ×2, teamexec_ ×2, askdesc_ ×1）にも同じく `lastActiveAt: new Date()` を追加。
   DB where で除外されるため機能上は不要だが、「`apps/server/src` の `prisma.session.create` は
   例外なく `lastActiveAt` を設定する」という機械的に検証可能な不変条件にするため揃えた
   （下記テストのトリップワイヤが成立する前提）。
4. `apps/server/src/routes/api.ts` の `GET /api/threads` 本体
   - `where` に `project: { deletedAt: null }` / `machine: { deletedAt: null }` を追加
     （`Session.machine` 側に掛ける。表示する `machineName`/`machineOnline` が `s.machine` 由来で
     `project.machine` とは別カラムのため）。
   - 一時セッション除外を `...buildEphemeralSessionIdExclusion()` として where に前倒し。
   - `orderBy: { lastActiveAt: { sort: 'desc', nulls: 'last' } }` を追加（Prisma 5.22 で型チェック済み、
     preview フラグ不要）。
   - `take: 500` → `take: limit`（≤50）。全フィルタが DB 側に移ったため「DB が返したものが
     そのまま応答」という不変条件を明示。`_count` 相関サブクエリの発行数も 500→50 に削減。
   - 横断・プロジェクト単位のどちらのモードでも同一の `where`/`orderBy` を通る。
   - `isEphemeralSessionId` の import と取得後フィルタ行を削除。

## 負債として記録（今回は対応しない）

- `apps/server/src/routes/api.ts` の `GET /api/threads` 内、先頭 user メッセージ取得が
  スレッドごとに `prisma.message.findFirst` を発行する N+1（50 往復）。`include.messages`
  の nested take に畳み込めば 1 往復にできるが、今回はスコープ外。
- `limit` 上限 50 かつ `hasMore` を返していない（横断モードで 51 件目以降があっても UI から
  判別できない）。
- `GET /api/sessions/active`（`api.ts`）は `orderBy: { startedAt: 'desc' }` はあるが `take` が無く
  （全 active セッションを取得して JS dedupe）、一時セッション除外・ソフトデリート除外も無い。
  同種の穴だが今回は未着手。
- `apps/server/src/index.ts` の起動時 sweep（`ended` への一括更新）は `teamexec_`/`crossquery_` を
  ハードコードしており `askdesc_` を含まない。含めるかどうかは起動時 sweep の挙動を変える判断になる
  ため、今回は意図的に据え置き（別サイクルで判断）。
