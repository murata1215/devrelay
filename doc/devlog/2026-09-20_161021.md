### auto-update の bake time の判定基準（実装根拠つき）

`agents/linux/src/services/connection.ts:2713,2721` の `handleVersionCheck()` が
`git log <remote-branch> -1 --format="%H %ai"` でリモート追跡ブランチの**最新コミットの
author date（`%ai`）**を取得し、`remoteDate` としてサーバーへ送信する
（同ファイル:2724,2775）。サーバー側 `apps/server/src/services/auto-updater.ts:114-118` が
`Date.parse(input.remoteDate)` でこれをミリ秒化し、`ageMin = (now - remoteMs) / 60000` を
`bakeMinutes`（既定 `DEFAULT_BAKE_MIN = 120`、同ファイル:31、env `DEVRELAY_AUTO_UPDATE_BAKE_MIN`
で上書き可）と比較する。`ageMin < bakeMinutes` なら `skip: bake time (...)` で配布しない
（同ファイル:117-118）。

つまり **基準は「コミットの author date」であり、push した壁時計時刻そのものではない**
（通常のコミット作成直後の push ではほぼ同時刻になるため実運用上は push 時刻とみなしてよいが、
過去日時でコミットを作成した場合はそちらが基準になる点に注意）。sweep 間隔は既定30分
（`DEFAULT_SWEEP_MIN = 30`、同ファイル:39）、同一機体への再試行クールダウンは
30分（`COOLDOWN_MS`、同ファイル:27）。

**revert を push した場合に配られるもの**: `git revert` も通常の commit なので、その author date
が新たな基準になる。revert コミットの内容は「`package.json` 3箇所と `pnpm-lock.yaml` を 0.2.80
（正確には revert 対象コミットの直前の状態）へ戻す」変更そのものであり、bake time 経過後の
sweep で全 Agent に同じ流れ（`git fetch && git reset --hard origin/main` → `pnpm install`
→ build）で配布される。0.3.278 の 234MB のネイティブバイナリは `pnpm install` 時に
`node_modules` から削除され、0.2.x 系の `cli.js` 同梱パッケージへ戻る。
