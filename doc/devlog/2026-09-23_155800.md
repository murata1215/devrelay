# 2026-09-23 15:58 JST ｜ サイクル2.1: DevRelay Sites Phase 1-B W3 Special Hosts Rollout

## 背景

W2（固定 21 host + dangou pilot = logger 22）は本番反映済み。残る「特殊構成 11 host」は
`sites-enable-access-log.ts` の安全装置（`isW3ExcludedHost` / `isEligibleForAutoLog` /
`assertSitesDPath`）によって構造的に自動適用の対象外（sites.d 手編集 or Caddyfile 直書き）に
なっていたため、手作業での個別適用（W3）が必要だった。本サイクルは read-only 調査と
`/tmp` ミラー検証を経た上での W3 本実行。

## 対象の切り分け（11 host → 実施 9 / 除外 2）

**実施 9 host**:
- sites.d 手編集（snippet import のみで対応可）: `pixterm-server.devrelay.io`, `pixterm.devrelay.io`
- Caddyfile 直書き（単体 `reverse_proxy`、snippet import のみ）: `draft.pixblog.net`,
  `news.pixblog.net`, `shelf.pixblog.net`, `manual.pixblog.net`, `clipped.devrelay.io`
- Caddyfile 直書き（host 固有 matcher が必要）: `devrelay.io`, `app.devrelay.io`

**除外 2 host（W4 へ分離）**: `pixblog.net`, `ribbon-re.jp`（+ `www.ribbon-re.jp`）。
いずれも既存の独自 `log { }` ブロックを持ち、単純に snippet を足すと 1 host に対して
logger が 2 つ生成され（`verifyAdaptedConfig()` の「1 host = 1 logger」不変条件に違反）、
かつ `log_skip` がリクエスト単位で効くため既存ログ側からも health checker 行が消えてしまう
（既存成果物の意図しない改変）。設計判断（logger を統合するか併存させるか）が必要なため、
別サイクル（W4）に分離した。

## `/tmp` ミラーで確定した実装上の論点（本番非接触で事前検証済み）

- **(F1) snippet スコープ**: `(sites_access_log)` は `sites.d/00-snippets` で定義され、
  Caddyfile の `import /etc/caddy/sites.d/*`（当時 126 行目）で初めて読み込まれる。
  inline host block（34〜123 行目）は定義より**前**にあるため、そのままでは
  `import sites_access_log` が `File to import not found` で失敗する。
  対策として先頭に `import /etc/caddy/sites.d/*` を追加すると `redeclaration of previously
  declared snippet` になり、glob パターン変更（`*.*` 等）も Caddy が拒否する。
  最終的に **`import /etc/caddy/sites.d/*` の行を Caddyfile 先頭へ 1 行移動する**方式を採用し、
  `/tmp` ミラーで adapt PASS を確認した。
- **(F2)** 既存 logger 持ち host（pixblog.net / ribbon-re.jp）への素の snippet 適用は
  1 host 2 logger になり構造検証が FAIL する（→ W3 除外・W4 分離の直接の根拠）。
- **(F3)** `auth.ts` の認証ミドルウェアはクエリ `?token=` を受理し、`/oauth/authorize` も
  `code`/`state` をクエリに載せる。Sites 標準の `format filter` は `Authorization`/`Cookie`
  ヘッダは消すが `request.uri` は消さないため、`devrelay.io`（`/api/*`, `/health`）と
  `app.devrelay.io`（`/api/*`, `/oauth/*`）は host 固有 `log_skip` matcher
  （`@drl_skip_credentialed`）を必須とした。`/ws/*` はハンドシェイク後にメッセージ内で
  認証するためクエリに資格情報が乗らず、対象外のまま通常記録している。
- sudo 境界: `/etc/caddy/Caddyfile` 本体の書き込みは sudoers NOPASSWD の対象外
  （`sites.d/*` に対する tee/rm と `systemctl reload caddy` のみが NOPASSWD）。
  Caddyfile 差し替えは人間が sudo コマンドを実行する設計とした（sudoers 自体は無変更）。
