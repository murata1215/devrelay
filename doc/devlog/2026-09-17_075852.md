# 2026-09-17 07:58 JST ｜ サイクルD0: Devin 承認ゲート調査

Devin CLI が DevRelay のプランモード規律を「外部システムの演技設定」と明言して従わなかった件を受け、Devin に承認ゲートを機構で効かせられるかを read-only で調査した。

コードとドキュメント（docs.devin.ai）を突き合わせた結果、Devin は plan フェーズでも exec フェーズと同一の argv（全ツール自動承認モード）で起動されており、プランモードの規律はプロンプト指示のみに依存していることを確認した。ただし「承認ゲートが一切無い」わけではなく、git 変更を事後的に自動復元するガードは実在する。この安全網が守れるのは git 管理下の可逆な変更のみで、リポジトリ外への書き込みや `git push`・`sudo`・パッケージインストールのような不可逆な操作は無防備なままだった。

機構的な締め付け（deny ルールの起動時注入など）が使えるかも調べたが、最終判断に必要な1点（自動承認モード下でユーザー権限ルールが効くか）はハーネスからは検証できず、実機確認が必要という結論に至った。今回は機構化を急がず、現状の限界を仕様として明記する方針を採った。

調査の過程で、作業ツリーに残っていた未commitの変更が実は2026-09-15の別修正（マシン一覧クリックで画面が真っ白になる不具合の対処）であり、その依存ファイルが直前のサイクルで commit から漏れていたためリポジトリが一時的にビルドできない状態になっていたことも発見した。今回のサイクルで正規のコミットとして取り込み、クリーンな環境から問題なくビルドできることを確認して解消した。
