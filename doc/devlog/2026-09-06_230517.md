# 2026-09-06_230517 #368 Phase2a Devin プランモード読み取り専用強制の再設計 — git 自動復元ガード方式へ全面転換（サブサイクル A〜E）

## 要求

#368 Phase1完了後、#363以来の`Exec()`許可/拒否リスト方式そのものを廃止し、Devinを常に`dangerous`相当で
起動したうえでgitによる自動復元ガードで書き込みを機械的に巻き戻す設計へ転換する依頼。1セッションで
巨大ファイル（`connection.ts`/`ai-runner.ts`/`session-store.ts`×3OS）を一度に読もうとしてauto-compact無限
ループで15.6分・約17.8万トークンを空回りし0ファイルのまま強制停止した反省から、Phase2aを5サブサイクル
（A〜E、1サブサイクル=1セッション）に分割したプラン`stateful-strolling-liskov.md`を作成・承認された。

## 調査（planモード）

- サブサイクルA〜Eの役割分担を設計: A=新規モジュール（呼び出し元ゼロ）、B=パーミッションモードマーカー追加
  （書くだけで誰も読まない）、C=実際に配線して挙動を変える唯一のサイクル、D=旧`Exec()`方式の死にコード削除、
  E=ドキュメント整備+全体静的検証+push。
- E（本サイクル）の時点でA〜Dはローカルcommit済み・未pushと判明。README.md/rules/project.mdが
  `devin-plan-config.ts`（Dで削除済み）に言及したままで実装と乖離していることも確認。
