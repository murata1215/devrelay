# 2026-11-23 20:42 JST ｜ サイクルSB-1b: 画面の Sandbox スイッチ（DB・サーバー・WebUI）

## 要求

SB-1a-2（commit 7bcfa35）で実装した Sandbox 実行（Windows サービス `NT SERVICE\devrelay-sandbox`
で Claude Code の起動を委譲し、外向き通信を許可リストに限定する機能）の対象プロジェクト指定が
`config.yaml` の手編集しかなかった。チャット画面の「自動承認/Ask無効/端末」の並びに
「Sandbox」スイッチを足し、プロジェクト単位で ON/OFF できるようにする。非対応 Agent（Windows 以外・
古い版）へ ON の指示が渡って制限なしで動く事故を防ぐため、サーバー側で fail-closed に止める。

## 実行

DB: `Project.sandboxEnabled`（既定 false）を追加（`db/changes/0036_project_sandbox_enabled.sql`、
`terminalMode` と同形）。shared: `AgentCapability` に `'sandbox-host'`（固定配列
`AGENT_CAPABILITIES` には含めず各 Agent の接続処理側で個別判定）、`AiPromptPayload`/
`ConversationExecPayload` に `sandboxEnabled?`、`sandbox.capabilityMissing` 文言（session/resume/
Prompt is too long を含まない）。サーバー: 純関数 `decideSandboxDispatch()` 新設、
`GET/PUT /api/projects/:id/sandbox`（terminal-mode と同形、ON には capability 要求・409）、
`sendPromptToAgent()`/`execConversation()` に拒否判定（throw）を追加し payload に
`sandboxEnabled` を同乗、ask/teamexec の fire-and-forget に `.catch()` を追加（無いと新しい throw
経路でタイムアウトまで無言で待つ）、`handleExec()` を try/catch 化。Agent: 新規
`sandbox-session-flag.ts`（sessionId 鍵の Map。既知の retryOptions 取りこぼし不具合は直さず
別経路に外出し）、`decideSandboxTarget()` にサーバー ON との OR 合成を追加（単一判定点の呼び出し
回数は不変）、`shouldDeclareSandboxHostCapability(platform)`（win32 のみ true）、
`sandbox-preflight.ts` のハードコード `capabilityDeclared: true` を配線。画面:
`sandbox-toggle-rules.ts` 新設、ChatPage.tsx に 4 つ目のトグル（非対応時は押せない表示 + title、
ON のまま非対応になっても OFF へは戻せる）。

## 発見

`zz1_verify.sql` は 0001〜0032 の一度限りのベースライン検証で 0033 以降の列を含んでいないため、
本サイクルでも更新対象外と判断（Plan の想定から変更）。`AGENT_CAPABILITIES`（固定配列）に
`sandbox-host` を含めなかったことで、macOS/Windows Agent は何もしなくても自動的に非申告のまま
（コード変更不要、Plan より少ない変更で同じ安全性を達成）。
