## 修正1: access log file が後から作られた場合の self-heal

**根拠** — `access-log-reader.ts` の `tailTick()` は `state.handle === null` のとき即 return するだけで、
Caddy が後から `sites.access.log` を作成しても検知しない構造だった（B1 導入直後・access log 未生成の
環境で `/api/sites/:host/stats` が永久に null のまま）。

**実装** — `!state.handle` の分岐を「即 return」から `open(currentPath, 'r')` の再試行に変更。

- `open` 失敗（ENOENT 等）→ state を一切変更せず、次 tick で再試行可能な状態を維持。
- `open` 成功 → 先頭から現在サイズまで全読みして `onLine` に流し、`state.handle`/`currentInode`/
  `offset`/`partial` を設定。`TickOutcome.reopened` / `ReaderState.reopenCount` を新設（可視化・テスト用）。
- rebuild は呼ばない（rotated/gz の再読による無駄・二重計上を避け、current 1 本だけを開き直す設計）。

**二重計上しない根拠** — `handle === null` になり得るのは「cold scan 時に current が存在しなかった」
「rotation で新 current の open が失敗した」の 2 経路のみで、いずれも「その時点の current の内容は
1 行も集計していない」ことが保証されるため、offset 0 からの全読みは安全。

**aggregator 側の整合** — self-heal で初めて行が入ると `coverage.measuredSince` が null のままになり
`computeStatsFromBuckets()` が `last30d.daily` を全 null にしてしまう不整合があったため、module level に
`observedOldestDate`（cold scan / tail 共通の単一 source of truth）を新設。純粋関数
`syncCoverageWithObservedOldestDate(coverage, observedOldestDate, today)` を新設し、`tick()` の後で
呼ぶことで `measuredSince` / `oldestCoveredDate` / `coveredDays` / `complete` を再計算する
（`truncated` / `truncatedReason` は保持）。`rebuild()` は cold scan 前に必ず `observedOldestDate = null`
へリセットする。

## 修正2: 404 を PV に含めない

**根拠** — `sites-rules.ts` の `isPageView(method, path)` は status を見ておらず、404 も PV に計上されていた。

**実装** — `isPageView(method, path, status)` に 3 引数化（呼び出し元は `access-aggregator.ts` の
`applyLineToBuckets()` 1 箇所のみ、grep 済みで他に caller なし）。`status === 200 || status === 304` を
追加条件とし、既存の除外パターン（`/api/*` 等）はそのまま維持。4xx/5xx カウンタの加算は PV 判定より
前にあり、順序は変更していない。

## 修正3: daily bucket / window を Asia/Tokyo 基準へ

**根拠** — `toDateKey(ts)` は `ts.slice(0, 10)`（UTC 日付）だったが、UI 表記は「今日 PV / Today UU」。

**実装** — `SITES_TIME_ZONE = 'Asia/Tokyo'` を新設。`toDateKey()` を固定オフセット方式
（`Date.parse(ts) + 9h` してから `slice(0, 10)`）に変更。日本標準時は DST が無く恒久的に UTC+9 のため、
この方式は Node 標準 API のみで完結しサーバー OS の TZ 設定に依存しない。入力が既に `YYYY-MM-DD`
形式ならそのまま返し、パース不能な入力は従来の `slice(0, 10)` にフォールバックする。`daysSince()` /
`shiftDate()`（aggregator）はラベル同士の暦日差を UTC 正午基準で計算するだけなのでロジック変更不要
（コメントで「引数は JST date key」であることを明記）。

`types.ts` の `StatsCoverage` / `SitesMeta` に `timeZone: 'Asia/Tokyo'` を追加し、`site-inventory-service.ts`
の meta 組み立て・`access-aggregator.ts` の coverage 初期値にそれぞれ 1 行追加。`apps/web/src/lib/api.ts`
の対応する型にも追加。`apps/web/src/i18n/messages.ts` は `sites.today` / `sites.colTodayPv` /
`sites.colTodayUu` の表示文言のみ `(JST)` を付与（en/ja 両方）。

JST 化により同一日に収束してしまい red 化。JST の日跨ぎ（UTC 15:00:00 前後）の ts に置き換えて修正。
