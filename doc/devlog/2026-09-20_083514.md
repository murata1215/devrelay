# raw-completion Phase 1.2 — permissionMode の見直し ＋ Fable 再検証

## 背景

前サイクル（Phase 1.1、commit `5323f79`）適用後の実機再スモーク（submission
`cmu8zcxcw00e5iwqczoz2am6n`）の (b)（ペルソナ非漏洩 / CLAUDE.md 非認知の確認）で、
`POST /api/agent/raw-completion` の応答が「Claude Agent SDK／Plan モードで動いている」と自称した。
`system` フィールドで system prompt を完全置換しているにもかかわらず Plan モードを名乗るのは、
SDK に渡していた `permissionMode: 'plan'` が **CLI 側でプロンプトへ system-reminder を注入している**
ためという仮説が立ち、本サイクルでその真偽を SDK ソースの実測で確認したうえで修正する。

人間指示の事前条件（プラン §2）: 「注入が無ければ変更せず、原因候補を報告して止まる」。
本サイクルは冒頭で SDK ソースを実測し、**注入あり**（変更してよい）と確定させてから実装した。

## 事前確認: SDK 内蔵 cli.js の plan-mode reminder 注入を実測確認

対象は `agents/linux/src/services/ai-runner.ts:992-998` が「内蔵 cli.js が健全なら
`pathToClaudeCodeExecutable` を設定せず内蔵版を使う」ため、raw-completion が実際に spawn するのは
`@anthropic-ai/claude-agent-sdk@0.2.77` 同梱の自前バンドル
`node_modules/.pnpm/@anthropic-ai+claude-agent-sdk@0.2.77_.../cli.js`（`sdk.mjs` 内
`z=G.pathToClaudeCodeExecutable; if(!z){...z=WV(x6,"cli.js")}` で確認）。

この `cli.js` を `grep -o` で調査した結果、以下の関数がガード付きで plan-mode reminder を
会話メッセージ列へ注入することを確認した:


`type:"plan_mode"` のイベントは `yqz()`（ディスパッチャ）経由で `Iqz()`（full）/ `uqz()`（sparse）へ
振り分けられ、それぞれ以下の verbatim 文言を `p1({content:K,isMeta:!0})` として会話メッセージへ
積む（`isMeta:true` の system-reminder ブロック。`systemPrompt` の完全置換では消えない別経路）。

**full 版**（`Iqz`、非サブエージェント）:

> make any edits (with the exception of the plan file mentioned below), run any non-readonly tools
> (including changing configs or making commits), or otherwise make any changes to the system.
> This supercedes any other instructions you have received.

> file (${A.planFilePath}). ${q} End turns with ${Fw} (for clarifications) or ${KD.name} (for plan
> approval). Never ask about plan approval via text or AskUserQuestion.

`PermissionMode` 型（`sdk.d.ts:1257`）は
`'default' | 'acceptEdits' | 'bypassPermissions' | 'plan' | 'dontAsk'` であり、`'default'` を渡せば
`toolPermissionContext.mode!=="plan"` の early return（`jhY` 冒頭）により、上記注入は一切発生しない。

**判定**: 注入あり・(b) の自称の直接原因として確定。プラン通り変更を実施した。

## 修正内容

### 対象ファイル（Agent 側のみ、linux/macos を byte-identical に維持）

1. `agents/{linux,macos}/src/services/raw-completion-mode.ts`
   - `RawSdkOverrides.permissionMode` の型を `'plan'` → `'default'`
   - `buildRawSdkOverrides()` の返り値の `permissionMode: 'plan'` → `permissionMode: 'default'`
   - 冒頭 JSDoc の「4層で多重防御」を「3層」に修正し、`permissionMode` の項を削除。
     代わりに「`permissionMode` は `'default'` 固定。SDK 内蔵 cli.js が `'plan'` 時に
     plan-mode reminder を会話へ注入し、`systemPrompt` 完全置換でも消せないため使わない
     （Phase 1.2 で実測確認）」という説明段落を追加
2. `agents/{linux,macos}/src/services/ai-runner.ts`
   - raw 分岐直前のコメント（旧: 「D1 の4層防御: ... 4. permissionMode:'plan'（万一1-3が
     漏れても編集系ツールを実行しない）」）を3層防御の説明 + `permissionMode:'default'` を
     使う理由（plan-mode reminder 注入回避）に書き換え
   - `SendPromptOptions.rawMode` の JSDoc にある同様の「D1 の4層防御」表記も3層に修正
   - **コード本体は無変更**（`Object.assign(sdkOptions, buildRawSdkOverrides(options.systemPrompt ?? ''))`
     のまま。`buildRawSdkOverrides()` の返り値が変わるだけで呼び出し側のロジックは影響を受けない）
3. `agents/{linux,macos}/tests/raw-completion-mode.test.mjs`
   - `permissionMode` のテストを更新: `assert.equal(overrides.permissionMode, 'default')` +
     回帰防止の `assert.notEqual(overrides.permissionMode, 'plan')`

### 変更しなかったもの

- `apps/server/**`（`raw-completion-api.ts` / `raw-completion-guard.ts` /
  `raw-completion-response.ts` / `agent-manager.ts` すべて無変更）
