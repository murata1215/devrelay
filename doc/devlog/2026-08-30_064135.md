# 2026-08-30 06:41 JST ｜ core#333: strictReadonly グロブ false positive 修正

要求: #332 直後の E2E で `ls doc/*` 等グロブ付き読み取りコマンドが plan strictReadonly で誤って deny
される問題を最小変更で解消し、deny メッセージと `ToolApproval.reason` に具体的な判定根拠を載せる。
exec モードの `canUseTool` と interactive/skip ポリシーは一切変更しないこと。承認時の人間からの追記で
「strictReadonly の allow 判定はユーザーカスタム allowedTools ∪ 対象OSの DEFAULT_ALLOWED_TOOLS の
読み取り系ルールの和集合で行う」ことが必須要件として追加された。

実行: 判定軸をコマンド文字列全体の前方一致からセグメント分割（`;`/`&&`/`||`/`|`/改行、クォート考慮）＋
セグメントごとの先頭実行ファイル名判定に変更。`packages/shared/src/constants.ts` に
`PLAN_READONLY_BASH_COMMANDS`/`PLAN_WRITE_BASH_COMMANDS`/`PLAN_WRITE_TOOLS` を新設し named re-export、
`agents/linux/src/services/plan-permission.ts` に純関数群（`splitShellSegments`/`hasWriteRedirect`/
`hasCommandSubstitution`/`tokenizeSegment`/`matchesBashRuleByTokens`/`decideBashCommand`）を追加し
`decidePlanPermission` を拡張（和集合計算・`detail` 追加）、既存 `matchesToolRule`/`isAllowedByRules` は
exec 用のため無変更で残置。macOS は自己完結方針により同一ロジックを新規ファイルとして複製。両
`ai-runner.ts` の strictReadonly 呼び出しのみ更新し exec ブロックは触らず。

検証: `pnpm build` 6 workspace フォアグラウンドで全 green、`agents/linux`/`agents/macos` の
`node --test` がそれぞれ34/34 green（既存9件中2件は reason文字列更新、新規20件はグロブ allow・fd複製
allow・git グローバルフラグ allow・パイプ allow・書き込み deny・複合コマンド deny・コマンド置換 deny・
和集合ポリシー3件）、`apps/server` 既存8/8 green（非退行）、`grep -c 'require('` = 0。両 `ai-runner.ts`
の `git diff` が import 行と strictReadonly ブロックのみ（exec ブロック0行差分）であることを確認。

発見: 旧実装は前方一致のため `git log --oneline > /tmp/x` が `Bash(git log *)` に一致し
リダイレクトで書き込みができてしまう抜け穴があった（回帰テストとして固定）。`UserSettings.allowed_tools_*`
にカスタム保存があると `DEFAULT_ALLOWED_TOOLS_*` への追加が一切効かない問題（副次発見1）は本サイクルでは
strictReadonly 判定側の和集合で回避したのみで、カスタム保存自体の一般解は別サイクル。DB DDLは不要
（#332で適用済み）、server再起動不要、全マシンの `u` が必須（実施は人間の反映後）。
