# #383 端末モード（PTY）× MCP: session ID エコーバック未実装によるapprove fail-closedの修正

## 背景

MCP `submit_instruction` はプロジェクトの「端末」設定を引き継ぐ。端末 ON のプロジェクトでは
`terminal-runner.ts`（agents/linux）が PTY で Claude TUI を起動するが、完了報告に AI セッション ID
（`aiSessionId`）を一切載せていなかった。その結果 `Session.planAiSessionId` が NULL のままとなり、
`approve_implementation` が `planAiSessionMissing` で fail-closed していた。

実測（TestClock、hp630g9、agents/linux を node.exe で実行）:
- 端末 ON: `cmtthpfkv018jb1md7qxc0yb0` → `planAiSessionId` NULL（`planTurnId` は保存あり）
- 端末 OFF: `cmttocjpx01f2b1mdot9h05te` → `planAiSessionId` `dd1ec4b0-…`、approve 成功、同一 session resume 成功

事前調査（read-only）でプラン `binary-gliding-kahn.md` を作成済み。詳細な真因の連鎖・argv 決定表・
Claude CLI 実測（`--session-id`/`--resume` 排他、`already in use` エラー文言）はプラン参照。

## 真因（1行）

`agents/linux/src/services/ai-runner.ts:1715` の `onOutput(suffix, true, runResult.usageData);` が
コールバックの第4引数（`extractedSessionId`）を渡していなかった。SDK 経路（`:1454-1456`）は渡している。

## 承認ノートに基づくコミット順

1. UUID 採番 + `--session-id` + 第4引数エコーバック（`planAiSessionId` が入る最小単位）
2. `agentScopeId` 抜け2件の修正（`terminal-runner.ts:1233` / `ai-runner.ts:1681-1694`）
3. 純関数モジュール切り出し + exit 処理統合 + 旧 CLI フォールバック
4. ドキュメント訂正（windows-agent-migration-plan.md / 381_windows_scope_wiring.md）+ changelog + INDEX

時間切れの場合は (1) 到達を優先し、green 単位で commit する。

  起動プレビュー行・診断ログにも反映。成功時 `onOutput()` と `cancelledByAskDisable` 時 `onOutput()`
