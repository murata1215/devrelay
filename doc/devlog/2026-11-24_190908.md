# サイクル SB-2.1.3: apply-sandbox-allowlist.ps1 がルール作成に失敗しても全遮断ルールを消す問題の修正

## 背景（hp630g9、commit a432474）

install 経由の反映が失敗し、state.json の error が
`unexpected_error: Microsoft.PowerShell.Commands.WriteErrorException at line 578`
になった（元のエラーではなく、それを表示する `Write-Error` 自体が例外になったもの）。
このときは fail-closed の全遮断ルール（`DevRelay-SandboxFailClosed-ipv4`）が残った。

その後、管理者 PowerShell で `&` 実行すると、527 行の `New-NetFirewallRule` が
CimException（HRESULT 0x80070057）「終了アドレスが開始アドレスより小さい」を出した
にもかかわらずスクリプトが続行し、`[OK] Applied generation e3b0c44298fc
(0 destination(s)).` と表示して全遮断ルールと旧世代を削除した。結果、ルールは
静的2本のみ（IPv4 が全開）になった。

## 真因（独立した2つ）

1. **`ConvertFrom-Ipv4Value` の桁あふれ（SB-2.1 からの既存バグ、527 行の直接原因）**
   `$v = [uint64]($v / 256)` を3回連鎖させていた。PowerShell の `/` は割り切れないと
   Double を返し、Double → `[uint64]` のキャストは切り捨てではなく最近接偶数丸めの
   ため、余り > 128 の桁で繰り上がりが上位桁へ混入する。許可先が空のとき、本来
   `0.0.0.0-126.255.255.255` / `128.0.0.0-255.255.255.255` になるはずの補集合が
   `0.0.0.0-127.0.0.255` / `128.0.0.0-0.0.0.255`（2本目は終了<開始）になっていた。
   実際に pwsh で旧実装を再現し確認済み（下記テスト参照）。IPv4 の世代ルールは
   SB-2.1 以降どのマシンでも一度も作成に成功していなかったことになる。
2. **失敗が握りつぶされた**: `New-NetFirewallRule` 等（NetSecurity モジュール）は
   呼び出し方によってはスクリプト冒頭の `$ErrorActionPreference = "Stop"` を
   見ない。`&` 実行では非終了エラーとして続行し、「作れたつもり」で旧世代と
   fail-closed ルールを削除した。さらに catch 内の `Write-Error` 自体が
   `$ErrorActionPreference = "Stop"` 下では終端エラーになり、元の例外
   （CimException）を `WriteErrorException at line 578` で上書きしていた。

## 修正内容

### `scripts/apply-sandbox-allowlist.ps1`

1. `ConvertFrom-Ipv4Value` を桁独立計算（`[math]::Floor` ベース、丸めが他の桁へ
   混入しない）に置換。
2. 範囲文字列の往復自己検査 `Test-Ipv4RangeStringsSelfCheck` を新設し、最初の
   `New-NetFirewallRule` より前に実行（形式不正を一切ファイアウォールに渡さない）。
3. `New-NetFirewallRule` / `Remove-NetFirewallRule` / `Get-NetFirewallRule` の
   全呼び出しに `-ErrorAction Stop` を明示（呼び出し方や ambient な
   `$ErrorActionPreference` に依存しない）。存在確認・グループ取得は新設
   `Test-FirewallRuleExists` / `Get-FirewallRulesInGroup` ヘルパー経由のみに統一
   （クエリ自体の失敗も「無い」扱い＝fail-closed側に倒す）。
4. 新世代に必要なルール名（`$expectedRuleNames`）が実在することを、旧世代・
   fail-closed ルールを削除する**前**に確認。1本でも欠けていれば削除を一切せず、
   このランで作った分だけロールバックして失敗終了（`rule_verification_failed`）。
5. `Write-Error` を全廃（4箇所）し `Write-Host -ForegroundColor Red` + 明示
   `exit` に変更。catch の先頭で `$err = $_` に退避し、ロールバック中の入れ子
   catch が元の例外を上書きしないようにした。正常終了に `exit 0` を明示。

### テスト

- `agents/linux/tests/sandbox-scripts-guard.test.mjs`: F1〜F6 の静的ガードを追加
  （-ErrorAction Stop の有無・桁連鎖除算の再発・往復自己検査の位置・実在確認の
  位置・Write-Error 不使用・catch 先頭の `$err` 退避）。E4 の旧 Write-Error
  テストは F5 に統合。既存テスト（ロールバック位置確認）がコメント長の変化で
  ウィンドウ不足になったため window を調整。
- `agents/linux/tests/sandbox-ipv4-range-math.test.mjs`（新規）: `.ps1` から
  IPv4/ポート算術系関数を波括弧対応で抽出し、PowerShell 7 (pwsh) を
  `/tmp` に一時展開して実際に実行・出力文字列を照合（空集合・1件・複数件・
  隣接IPのマージ・ポート補集合、install 側の fail-closed リテラルとの一致、
  および旧実装の再現で `128.0.0.0-0.0.0.255`（終了<開始）が実際に出ることを
  確認）。pwsh が無い環境では自動スキップ。pwsh と Windows PowerShell 5.1 は
  除算・キャストの丸め挙動が同一（.NET の `Convert.ToUInt64(double)` 仕様）の
  ため、この検証はそのまま 5.1 の実機挙動の再現として有効。SB-2.1.2 で修正した
  `List[object]` + `@()` バグは 5.1 固有で本テストの対象外。

## 検証結果

- `node --test tests/sandbox-scripts-guard.test.mjs tests/sandbox-ipv4-range-math.test.mjs`
  （pwsh を一時導入した状態）: 全 pass（guard 64件、range-math 16件）。
- `node --test --test-concurrency=1 tests/`（agents/linux 全体）: 1795件中
  1793 pass / 2 skip（pwsh 未導入時の range-math 一部・既存の pre-existing skip）
  / 0 fail。
- `.ts` ファイルは無改造のため `pnpm build` 不要・サービス再起動不要。
- pwsh 実行で、空集合時の補集合が install-sandbox-host.ps1 の fail-closed
  リテラル（`0.0.0.0-126.255.255.255` / `128.0.0.0-255.255.255.255`）と一致する
  ことを確認。1件（203.0.113.5:5432）時は IPv4 3本・TCP ポート補集合
  `1-5431`/`5433-65535` の想定どおりの結果。
- hp630g9 実機確認（けいすけが実施予定）: install 再実行後、管理者 PowerShell
  での `&` 実行・`-File` 実行の両方で成功し、ルールが静的2本+世代ルール1本
  （`DevRelay-SandboxGen-e3b0c44298fc-ipv4`）の3本になり全遮断ルールが消えている
  こと、世代ルールの範囲が `0.0.0.0-126.255.255.255` / `128.0.0.0-255.255.255.255`
  であることを確認する予定。

## 対象外

許可リストの仕様、Agent 側の TypeScript、その他の残課題。
