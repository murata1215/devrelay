## 発見
- SDK の `Query.request()` のような**型定義に存在しない実行時専用 API**（#339 参照）は、戻り値の
  「形」自体もドキュメント化されていないため、SDK 自身の内部実装（他のメソッドが同じ `request()`
  をどう使っているか）を読むのが最も確実な裏取り方法だった。`generateSessionTitle()` 等の
  既存メソッドが `(await this.request(x)).response` と1段剥がしているのを見つけたことが
  決め手になった
- 「即時 ack は出るが直後に失敗する」という症状は、非同期処理の**受付自体**（#341 で直した
  無反応区間）とは別の層のバグであることを示す強いシグナルだった。ack と失敗が同一分＝ほぼ
  同期的だったことから、60秒/120秒のタイムアウト（#341）ではなく成功パスのロジック自体を
  疑うべきだと早期に絞り込めた
- 封筒からの unwrap をテスト困難な `claude-login.ts`（SDK 依存）に直接書かず、外部 import
  ゼロの別ファイルに切り出したことで、SDK のシンボリックリンクが壊れている環境でも
  `node --test` でロジックを検証できた（#337/#339/#341 と同じ設計判断の継続）
