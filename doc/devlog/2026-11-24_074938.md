# 2026-11-24 07:49 JST ｜ サイクル SB-2.1.2: apply-sandbox-allowlist.ps1 の型エラーと IPv4 全開問題の修正

## 要求

hp630g9（SB-2.1.1 適用後）で `install-sandbox-host.ps1` の最後の反映が必ず
`[WARN] apply-sandbox-allowlist.ps1 reported exit code 1`。タスク経由・管理者 PowerShell での
手動実行も同じく失敗する。state.json は `"result":"error"`、`"error":"unexpected_error: <ローカライズ
された日本語>"`。`$Error` から取り出した元の例外は `System.ArgumentException`、発生行は
`apply-allowlist.ps1:426` `$destinations = @($validDestinations)`。結果として IPv4 の遮断
ルールが 1 本も無い状態（静的 2 本のみ）。範囲は型エラーの修正・fail-closed 化・エラー記録の
3 点、対象外は許可リストの仕様・Agent 側 TypeScript。

## 調査結果（真因）

`$validDestinations` は `New-Object System.Collections.Generic.List[object]`（362 行）で
作った `List[object]`。Windows PowerShell 5.1 は `@( )` を実行時にバインダで解決し、
`List<object>` だけ専用の高速経路を持つ。その経路は列挙子を `List<object>.Enumerator`
（構造体）型の式として渡すが、その先のヘルパーの引数型は `IEnumerator` のため、組み立てた式
が `System.Linq.Expressions` に拒否され `ArgumentException`（日本語で「引数の型が一致しません」）
になる。空集合・1 件・複数件のいずれでも発生し、`$destinations` の型指定も無関係。`List[string]`
は無事（同じ install 実行内で `Invoke-NativeCommand` の `Output = @($lines)` が 27 箇所成功済み）。
公開報告3件（dkj-claude-plugins#2040, AI-TwinCAT-Skill#75, Starlight PR#522）で repro と回避策
（`.ToArray()` / `[object[]]` キャスト）が一致。

3 スクリプト横断で `@($var)` パターンを機械的に洗い出した結果、`List[object]` 変数への
`@()` は 426 行ともう 1 箇所（415 行 `rejected = @($violations)`、`request.json` が不正な場合に
必ず落ちる潜伏バグ）の 2 箇所のみ。426 行で死んでいたため **426 行以降は一度も実機で動いた
ことがない**ため、同じ DLR 経路に依存する書き方（`List[object]` のパイプ・入れ子インデックス
代入・関数戻り値が 1 件だけの配列になる経路）もあわせて点検・修正した。

## 実行

### apply-sandbox-allowlist.ps1
- `List[object]` は作ったスコープから出す瞬間に必ず `.ToArray()`（`@()` は使わない）という
  単一ルールに統一: `$destinations`（426 行相当）、`rejected`（415 行相当）、
  `Get-Ipv4Complement` の戻り値（`Merged`/`Complement`）。
- `$holeList | Sort-Object` も同じルールに合わせ `$holeList.ToArray() | Sort-Object` に変更
  （ピコが安全という未検証の主張に依存せず、1本のルールで統一する判断）。
- `Get-Ipv4Complement`/`Get-PortComplementRanges` 内の入れ子インデックス代入
  `$merged[$merged.Count-1]['End'] = ...` をローカル変数 `$last` 経由に変更（ハッシュテーブルは
  参照型のため挙動は不変、可読性と保守性のため）。
- `Format-Ipv4RangeStrings`/`Get-PortComplementRanges` の呼び出し元で結果を `@()` で包む
  （PowerShell の `return $array` が 1 要素配列をスカラーに畳んで出力ストリームに流す仕様のため、
  0/1/N 件のいずれでも配列として受け取れるようにする）。
- fail-closed: 新定数 `$FailClosedRuleName = "DevRelay-SandboxFailClosed-ipv4"`（install と
  バイト一致）。新世代のルールを全部作り終えた**後**にだけ、旧世代削除と同じ場所でこのルールを
  削除する。作成そのものは install 側のみが行う（apply 自身は作らない。毎回の再反映で一瞬
  全遮断すると許可済み宛先の接続が切れ、反映が失敗すると許可が戻らないため）。
- エラー記録: `Format-ErrorCode` ヘルパーを新設し、state.json の `error` に
  `rule_creation_failed: System.ArgumentException at line 426` のように ASCII の
  `.NET 型名 + 行番号`のみを書く（`Exception.Message` は書かない）。画面の `Write-Error` 2 箇所
  には行番号を含める。

### install-sandbox-host.ps1
- 同じ `$FailClosedRuleName` 定数を追加。
- Step 11 の全リセット直後・`$LocalUserSddl` 定義の直後（静的 2 本より前）に fail-closed
  ルールを作る。範囲は SB-2.1 で削除した旧静的ルールと同一文字列
  （`"0.0.0.0-126.255.255.255","128.0.0.0-255.255.255.255"`、SB-1 で hp630g9 実機検証済み）。
- WARN 分岐（反映スクリプトの exit code ≠ 0）で state.json の `error` を 1 行表示するように
  追加（子プロセスは `-WindowStyle Hidden` で画面出力が見えず、state.json を手で開かないと
  原因が分からない状態を解消。read/parse 失敗は無視して install 自体は止めない）。

### uninstall-sandbox-host.ps1
コード変更なし（削除条件が「DisplayName `DevRelay Sandbox*` ∪ Group `DevRelay Sandbox`」の
ままで fail-closed ルールも確実に消える）。コメントのみ更新。

### 静的ガード（agents/linux/tests/sandbox-scripts-guard.test.mjs）
- A4 を更新: install が直接作る `New-NetFirewallRule` を 2 本→3 本、`-Name` 判定を
  `"DevRelay-SandboxStatic-"` 固定から `"DevRelay-Sandbox` ワイルドカード／`$FailClosedRuleName`
  変数のいずれかに緩和。
- 新規 describe ブロック（E1〜E4、ファイル先頭の失敗 ID 一覧にも追記）:
  - E1: 3 ファイル横断で `List[object]` 宣言を機械的に抽出し、コード行に `@($変数)` も
    `$変数 |` も無いことを検証（`List[string]` は対象外）。
  - E2: install の fail-closed ルール作成が apply 呼び出しより前・範囲とルール名リテラルが
    install/apply で一致。
  - E3: apply の fail-closed ルール削除が最後の `New-NetFirewallRule` より後・rollback
    ブロック内に無い。
  - E4: state.json の `error` に `Exception.Message` が無い・`Format-ErrorCode` が
    `GetType().FullName`/`InvocationInfo.ScriptLineNumber` を使う・`Write-Error` が行番号を含む。
