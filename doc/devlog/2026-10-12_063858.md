# 高辻ナレッジ サイクル4 — ナレッジ回答（RAG）: ひとつの検索箱で根拠カード＋ストリーミング回答

日時: 2026-10-12（JST）

## 目的

サイクル1〜3 で作った `/knowledge` は RAG の「R」（検索）だけだった。本サイクルで「AG」
（AI 回答）を足し、検索箱に質問（でもキーワードでも）を打てば、従来どおりの根拠カードが
即座に並ぶのと同時に、上の回答欄に AI の答えが文字で流れてくる体験にする。各文の `[n]` は
下のカードの番号と一致し、クリックでそのカードへ、もう一度クリックでスレッドビューアへ。

対象: `apps/server`・`apps/web`。agent / flutter / Lite / ChatPage は 0 行変更。

## 指示書との食い違い・ユーザー承認の最終決定

プラン段階の調査で、指示書の前提と実装現状が食い違う点を 5 件（A〜E）発見し、プランで明示して
承認を得た。実装はすべてユーザー承認どおり:

1. **鍵解決（指示書 D3 は取り下げ）**: `DEVRELAY_ANSWER_API_KEY` **専用・共有のみ**。個人の
   Chat AI キーにも汎用 `OPENAI_API_KEY` にもフォールバックしない（費用をキー単位で用途別に
   分けて見るため）。provider は OpenAI 固定、model は `DEVRELAY_ANSWER_MODEL`（既定
   `gpt-4o-mini`）。未設定なら回答機能は「キー未設定」の文言を返し、検索は従来どおり動く
2. **経過秒表示**: ライブのカウンタは出さない（`setInterval` 禁止ガードは緩めない）。スピナー
   のみ表示し、完了後にサーバーの `elapsedMs`・`model`・`usage` を小さく表示する
3. **`useWebSocket` import ガード**: `KnowledgePage.tsx` に限り解除（`components/knowledge/*`
   は引き続き禁止）。ただし`KnowledgePage` が素朴に既存 `getTabId()` を使うと、chatId
   （`web:${userId}:${tabId}`）が ChatPage と衝突し、**WS 切断中に完了していたチャットの応答を
   接続時に無条件 flush で消費してしまう実害**があると判明（`platforms/web.ts` の接続処理を
   読んで発見）。`${getTabId()}:knowledge` という専用 tabId で chatId の名前空間を分離して回避
   （`getUserContext` は未知の chatId に参加登録を一切行わないため、ChatPage 側に副作用ゼロと
   確認済み）
4. **Markdown レンダラ＋平文ガード**: `AnswerMarkdown.tsx`/`KnowledgeAnswerPanel.tsx` の 2 ファイル
   に限り markdown 描画を許可（`dangerouslySetInnerHTML` は使わない＝生 HTML はテキストのまま）。
   `KnowledgeResultCard.tsx`/`KnowledgeThreadViewer.tsx` は変更なし
5. **チャンク全文＋兄弟チャンクの再取得**: `isTurnVisible` で可視判定し、`summarize` アクションで
   監査

## §10 確認事項の調査結果（実装前のプラン段階で確定）

1. WS 特定ユーザー送信口: `platforms/web.ts` の `sendWebRawMessage(chatId, msg)`（既存）。
   `chatId = web:${userId}:${tabId}` のタブ単位のため、ブラウザが `tabId` を body に載せる方式
2. `useWebSocket` 購読口: ハードコード `switch`。型 3 変種・任意コールバック 3 本・`case` 3 本の
   純加算で対応（既存 9 種は無変更）
3. モデル名の外部指定: `resolveChatProvider` に model 引数が無かった → 任意第 4 引数を追加
4. 言語解決: `resolveSessionLanguage(sessionId)` のみで userId 版が無かった → `resolveUserLanguage
   (userId)` を新設し、`resolveSessionLanguage` をそれに委譲（挙動不変）
5. チャンク全文の取得口: `searchKnowledge` は最良チャンク 1 個の `snippet` のみ返す → 新規
   `loadKnowledgeTurnTexts()`（`knowledge-service.ts`）を追加
