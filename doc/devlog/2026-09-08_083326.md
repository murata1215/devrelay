## 発見（既知分、C1 開始時点）

- **`session-scope.ts` は「外部 import ゼロの純関数のみ」という既存規約があるため**、
  `node:path` を要する `resolveScopeDir()` を別ファイル `scope-dir.ts` に分離した
  （linux/macos 両方に新設、byte-for-byte 一致）。
- **完了コールバック内で `aiResult.extractedSessionId` を直接参照すると
  `Cannot access 'aiResult' before initialization`（TDZ）で全 AI 完了報告が例外化する**
  （`const aiResult = await sendPromptToAi(..., callback, ...)` の Promise 実行中に
  callback が発火するため、`aiResult` 変数はまだ初期化されていない）。対策として
  `OutputCallback` の第 4 引数 `extractedSessionId` を追加し、コールバック内では
  必ずその引数を使う方式に変更した。回帰テスト `output-callback-tdz.test.mjs` で固定。
- **Windows agent は #348 / #375 も未適用**のため、core#336 の移植は別サイクルに切り出す。
  Windows 機からの MCP approve は `planAiSessionId` が null のまま fail-closed になる
  （サーバー側は Session の該当列が null なら resume を諦め新規セッションにフォールバックする設計）。
- A / B とも 30 分枠内で devlog に到達できず、C1 で「devlog を冒頭で作ってから実装する」方式に
  変更した（本ファイルがその実例）。
- **（承認済み判断）M1**: macOS の `handleAiPrompt` は元々 `forceNewSession` を payload 型に
  持たず握り潰していた。`decideResume()` の契約は `explicit > forceNewSession > stored` の
  3 段優先順位であり、第 2 引数を落とすと byte-for-byte 一致の `resume-priority.ts` が
  OS ごとに違う意味になってしまうため、linux と同じく `payload.forceNewSession` を渡すよう
  修正した。結果として macOS でも MCP submit の `forceNewSession` が効くようになる
  （linux と同一挙動へ収束。従来 macOS だけ MCP submit 後も resume してしまう潜在バグだった
  可能性があるが、今回のスコープでは「linux と揃える」ことのみを目的とし詳細調査はしていない）。
- **（承認済み判断）`session-store-scope.test.mjs` の macOS 調整**: macOS の `session-store.ts`
  には `SessionMeta`/`loadSessionMeta`（Plan→Plan resume 判定専用の `claude-session-meta.json`）が
  存在しない構造差があるため、テストの `EXPECTED_FILES` から `claude-session-meta.json` を除いた
  7 ファイルに変更し、`saveClaudeSessionId()` 呼び出しも 3 引数版（`mode` 引数なし）に合わせた。
  ケース数 3 は linux と同一のまま維持。
