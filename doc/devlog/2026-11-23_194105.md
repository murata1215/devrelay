# 2026-11-23 19:41 JST ｜ サイクルSB-1a-2: チャットから Sandbox で 1 往復できるようにする

## 要求

SB-1a-1/1.1 で作成済みの Sandbox 部品（Sandbox Host・中継プロキシ・ランチャ・CLI）を
`ai-runner.ts`/`connection.ts` に配線し、設定ファイルで指定したプロジェクトについて
チャットからの実行で claude が Sandbox Host 経由で起動し 1 往復できるようにする。
あわせて selftest の残課題 a（プロキシ経由拒否が未確認）・b（acl-audit が拒否と不在を区別できない）・
c（claude-roundtrip がプロセス終了しない）を修正する。人間の追加指示: `config.yaml` の変更を
`u`（再起動しない場合がある）に依存せず確実に反映する方式にすること。

## 実行

- `sandbox-target.ts` 新設（純関数 `decideSandboxTarget()`、対象/対象外/判定不能の3値、
  設定ミスは fail-closed で判定不能に倒す）。`sandbox-readiness.ts` に拒否理由5件 +
  `decideSandboxTurnEligibility()`（claude以外/端末/raw/一時セッション/引継ぎ/判定不能を拒否）。
- `sandbox-preflight.ts`/`sandbox-proxy-session.ts` 新設: CLI にあった `runSandboxPreflightCheck()`
  とプロキシ用意ロジックを移設し、`effectiveAiTool`/`terminalMode` を引数化。中継プロキシは
  参照カウント付き共有に変更（selftest 全体を1リースで包み a を根治）。
- `sandbox-launcher.ts` に `createSandboxSpawnFunction()` 追加（SDK の `spawnClaudeCodeProcess`
  契約を満たす同期関数）。`sandbox-env.ts` に `buildSandboxSpawnEnv()`（SDK 追加 env のうち
  `CLAUDE_CODE_*`/`DEVRELAY_*` 接頭辞だけ許可、禁止キーは null で明示削除）。
- `ai-runner.ts` の `sendPromptToAiImpl()`（端末/SDK分岐より前の単一チョークポイント）で
  **判定のたびに `loadConfig()` を読み直す**設計にした（人間の追加指示対応: `u` はビルド成果物の
  鮮度ゲートで変更が無ければ再起動しないため、起動時キャッシュの `AgentConfig` では
  `sandbox.projects` の追加・削除が反映されないまま古い判定が続く恐れがあった。これにより
  設定変更は次のチャット送信から即座に反映され、再起動は不要）。
- `connection.ts` は `handoverTurn` を `sendOptions`/`retryOptions` に1行ずつ追加するだけ。
- selftest の b: 絶対パス表示 + Agent 側存在確認 + プロジェクト内ファイルの対照読み取りを追加
  （`interpretSandboxFileReadProbe()`）。c: `sandbox-proxy.ts` の `close()` が CONNECT 中継中の
  socket を `destroy()` せず無限に待っていたバグを修正（socket を Set で追跡）。

## 発見

- selftest a の真因は、`sandboxSelftestCommand()` が実行前確認用に `withSandboxProxy()` を呼んで
  いたが、各プローブ関数も個別に `withSandboxProxy()` を呼んでいたため、1本目終了時点でプロキシが
  閉じ、2本目が「未確認（exit=7）」になっていた。
- Plan で懸念していた `cmd.exe /c type <path> > nul` の引数配列渡しによるリダイレクト不成立は、
  `QuoteArgument()` が空白/引用符を含まないトークン（`>` 単体）をそのまま通すため実際には発生しない
  と判明。該当箇所の引数形式は変更していない（単一文字列化は cmd.exe の `/c "..."` クォート解釈と
  衝突するリスクがあり、既存形式より安全と言えないため）。
