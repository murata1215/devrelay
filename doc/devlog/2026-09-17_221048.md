# 2026-09-17 22:10 JST ｜ uninstall-agent.ps1 の GUI 版取り逃しを修正（実機ドライラン実証分の追撃）

前サイクル（`2026-09-17_210554.md`、commit `7fcb16a`）で `scripts/uninstall-agent.ps1` を新設した直後、ユーザーが実際に lfuser 機で `irm https://raw.githubusercontent.com/murata1215/devrelay/main/scripts/uninstall-agent.ps1 | iex` を実行し `N` で止めて診断だけ取った。その結果を貼ってもらい、真因（GUI 版と CLI 版が同一 `%APPDATA%\devrelay\config.yaml` を共有し同一トークンで二重接続）が実機の物証つきで確定した一方、`[1/6]` の一覧に **`GUI版アンインストーラ:` の行が一件も出ていない** という、スクリプト自身の取り逃しも実証された。

## 見つかった穴（実測1件＋コード調査4件＋安全性1件）

調査の結果、取り逃しは1件ではなく計6件のギャップがあると判明した。

- **H1（実測で確定）**: GUI アンインストーラのレジストリ検出条件が `DisplayName -eq "DevRelay Agent"`（完全一致）と `PSChildName -like "*io.devrelay.agent*"` の2条件のみだった。electron-builder の NSIS は Uninstall キー名に appId ではなく GUID を使うため後者は原理的に外れ、前者も表記ゆれで簡単に外れる。実機で0件ヒットが実証された。
- **H2**: GUI 本体のインストール先パス（`%LOCALAPPDATA%\Programs\DevRelay Agent\`）を一切見ていなかった。削除対象にも残留スキャンにも入っていない。
- **H3**: Electron の userData（`%APPDATA%\DevRelay Agent\`）が対象外だった。`agents/windows` は `app.setName()` を呼ばないため、Electron の既定挙動で productName 配下に cache/localStorage を作る（config.yaml を共有する `%APPDATA%\devrelay\` とは別物）。
- **H4**: Startup VBS のもう一つの名前が対象外だった。`scripts/install-agent.ps1`（agents/linux 由来、CLI 版の一般的な導入経路）は `DevRelay Agent.vbs` を作るが、`agents/windows/src/cli/commands/setup.ts:147`（GUI 版本体が持つ CLI サブコマンド）は `devrelay-agent.vbs`（小文字・ハイフン区切り）を作る。
- **H5**: NSIS が作る Start Menu / デスクトップのショートカットが対象外だった（electron-builder 既定で `shortcutName` = productName）。
- **H6（安全性の懸念）**: 削除対象を増やすほど誤削除のリスクが上がるにもかかわらず、`Remove-Item -Recurse -Force` に対する安全ガードが一切無かった。`${env:ProgramFiles(x86)}` は `$env:ProgramFiles(x86)`（波括弧なし）と書くと空文字列になり `Join-Path "" "DevRelay Agent"` のような事故の余地があった。

## 実装内容（`scripts/uninstall-agent.ps1` のみ、他ファイル無変更）

1. **`Test-SafeDeletePath` 関数を新設**（H6）。ユーザープロファイル / LOCALAPPDATA / APPDATA / Program Files 配下のみ許可し、空文字列・ドライブ直下（`C:\` 等）を弾く。Windows PowerShell 5.1 互換のため `?:`/`??` は使わずすべて `if`/`else` で書いた。既存の未ガード箇所（`$ConfigDir`・スキルフォルダの削除）も含め、スクリプト内の全 `Remove-Item -Recurse -Force` をこの関数経由に統一した。
2. **GUI インストール先の検出を3経路化**（H1/H2）。優先順位順に (1) `[1/6]` で既に列挙済みの `$RunningProcs`（`Win32_Process` の `CommandLine -like '*devrelay*'` フィルタ結果）から `Name -like "DevRelay Agent*.exe"` を絞り込み `ExecutablePath` の親ディレクトリを取る — レジストリの状態に依存しない最も確実な信号 (2) 既知パス（`%LOCALAPPDATA%\Programs\DevRelay Agent`・`%ProgramFiles%\DevRelay Agent`・`${env:ProgramFiles(x86)}\DevRelay Agent`）の `Test-Path` (3) レジストリ検索を緩和し、`DisplayName`/`DisplayIcon`/`InstallLocation`/`UninstallString`/`Publisher`/`PSChildName` のいずれかが `-like "*devrelay*"` でヒットすれば検出。3経路の結果は `$GuiInstallDirs`（重複排除）と `$GuiUninstallString` に集約し、`[1/6]` の一覧に必ず `GUI版: <path>` として出す。
3. **GUI 版の削除を3段フォールバック化**（H1・`[5/6]` 書き換え）。(1) レジストリの `UninstallString` があればそれを `/S` で実行 (2) 無ければインストールフォルダ内の `Uninstall*.exe`（electron-builder が置く命名規則）を探して `/S` で実行 (3) `Start-Sleep -Seconds 3` を挟んでフォルダの残存を確認し、まだ残っていれば `Test-SafeDeletePath` を通した上でフォルダごと直接削除する（NSIS アンインストーラは自分自身を temp にコピーして非同期で削除処理を行うため、`-Wait` だけでは消え切らない場合があるための保険）。
4. **取りこぼしパスを対象に追加**（H3・H4・H5）。`%APPDATA%\DevRelay Agent\`（Electron userData）、Startup の `devrelay-agent.vbs`（もう一つの名前）、Start Menu フォルダ・ショートカット（`.lnk`）・デスクトップショートカットを `[1/6]` のスキャンと `[3/6]`/`[4/6]` の削除に追加した。すべて `Test-SafeDeletePath` 経由。`%APPDATA%\Electron\` は他の Electron 製アプリと共有されるため削除対象にはせず、残留スキャンで `NOTE`（`WARNING` とは別の DarkGray 表示）として報告のみに留めた。
5. **残留スキャンの拡充**。`$ResidualPaths` に `%LOCALAPPDATA%\Programs\DevRelay Agent` を追加（報告のみ・削除しない原則は維持）。
6. **ヘッダーコメント更新**。冒頭の「削除対象:」「削除しないもの:」の一覧を上記の追加内容に合わせて更新し、「安全対策:」の項目を新設して `Test-SafeDeletePath` の挙動を明記した。
7. **`.devrelay-output/dr-agent-uninstall.ps1` に同内容コピーを再出力**し、`diff` で `scripts/uninstall-agent.ps1` と完全一致することを確認した。
