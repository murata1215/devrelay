# 2026-10-23 13:51 JST ｜ サイクル: Agentインストールのclone先切替（会社private対応）

社内展開のため、本流（個人GitHub public）はそのまま、Agentのインストール・自己更新（`u`）だけを
会社private リポジトリへ向けられるようにする依頼。認証はFine-grained PAT（対象repo限定・Contents:
Read のみ）。PAT保存方式として `git config --local` のURLスコープ `http.<repoUrl>.extraHeader` を採用し、
credential helperを一度も経由しない設計にした（開発者本人のgithub.com資格情報に一切干渉しない、
URL/画面/ログにPATが出ない、サーバー/DB/WSには一切送らない）。

install-agent.sh/.ps1 に `--repo`/`$env:DEVRELAY_REPO_URL`（PATは`DEVRELAY_REPO_TOKEN`env or対話入力）
と `--repo-auth-only`（PATだけ差し替える軽量経路）を追加。既存インストール機で repo を切り替えても
古いoriginからpullし続ける穴（reconcile_remote未実装）と、Linux/macOSの`u`が`git fetch`の終了コードを
見ておらず認証失敗時に古いdistで静かにrestartする穴（Windows分岐は#356 B4で既に対応済み）を根治。
Linux版`connection.ts`にspawn前のpre-flight認証チェック（`git ls-remote`）とfetch/reset exit code判定を
追加し、失敗時はAgentを生かしたままチャットへ「PAT期限切れ・権限不足の可能性」を返す。macOSは
`getExecEnv()`への非対話化env注入のみ対応（exit code判定・pre-flightは対象外、ユーザー承認済み）。

WebUIは`GET /api/machines/:id/token`に`agentRepoUrl`を追加（`DEVRELAY_AGENT_REPO_URL`未設定時は
従来と完全同一文字列、PAT埋め込みURLはサーバー側で拒否）。新規`install-command-rules.ts`で
インストール一行コマンドを純関数化しテストで非退行を固定。新規doc `doc/company-repo-sync.md`に
個人⇄会社2リモートの同期・還元手順、PATローテーション、トラブルシュートを記載。

検証: `pnpm build`全6ワークスペースgreen（Node18警告は既存環境要因、Vite 20+警告も同様）。
テストserver1273/1273（新規10）・web884/884（新規11）・linux1099/1099（新規15）・macos657+1skip
（新規15、既存flake1件は単独実行で再現し本変更と無関係と確認済み）green。install-agent.shの
新規関数（write_repo_auth/reconcile_remote/is_repo_auth_failure）は一時gitリポジトリで実機動作確認
（冪等性・chmod600・PAT非平文化・origin張替えを個別に確認、検証後削除）。DBマイグレーションなし。
