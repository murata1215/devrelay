# get_answer / get_plan から進捗表示行を除外

## 背景

`ask_project` の実機 E2E で、MCP `get_answer` の `answer` に

```
📊 Rate Limit: 5h: 0%
🔧 Bashを使用中...
🔧 Readを使用中...
（×8）
...本文...
```

のような進捗表示がそのまま含まれていた。`get_plan` の `planMarkdown`/`summary` も同じ
`Message.content`（`agent-manager.ts:763-765` の `contextPrefix + mark + output`）を
素で返しているため同様に発生する。音声クライアント（チャッピー）がこれをそのまま読み上げると
不要な内容を受け取ることになる。

## 調査結果

混入経路は 3 種類のみと特定した。

| # | ノイズ | 生成元 | 書式 |
|---|---|---|---|
| A | `📊 Rate Limit: 5h: 0% \| 7d: 12%` | `agents/{linux,macos}/src/services/connection.ts` | `` `📊 Rate Limit: ${parts.join(' \| ')}\n` ``（i18n を通らない英語ハードコード） |
| B | `🔧 Bashを使用中...` / `🔧 Using Bash...` | `packages/shared/src/i18n.ts` `progress.usingTool` | ja `🔧 {tool}を使用中...` / en `🔧 Using {tool}...` |
| C | `⏳ [123s 経過] Cogitating for 28s…` | `agents/linux/src/services/terminal-runner.ts`（terminal-mode、linux のみ） | `` `\n⏳ [${elapsedSec}s 経過] ...\n` `` |

devin/codex 系の進捗（💻/🔍/📝/📖）は全て `⏳ ` prefix 付きで送られ `connection.ts` の
`output.startsWith('⏳')` 判定で除外されるため対処不要と確認済み。`📊 Context: ...`
（`output-parser.ts`）は `console.log` のみで本文に混入しない。

**C は `#276` 規約（⏳ 始まりのチャンクは最終回答から除外）の抜け穴**: terminal-runner.ts が
先頭に `\n` を付けて送出するため、チャンク単位の `startsWith('⏳')` 判定を素通りして
`Message.content` に混入する（`Project.terminalMode` のプロジェクトでのみ発生）。
**Agent 側の根治（各機 `u` が必要）は今回やらず**、サーバー側の返却時整形で行単位に吸収した。
**別課題として残っている**（`rules/project.md` に記録済み）。

## 実装

- `apps/server/src/services/progress-markers.ts` を拡張。既存の `isProgressMarkerLine()`/
  `stripProgressMarkers()`（🔧 行専用、`build-summarizer.ts`/`agent-manager.ts` が使用中）の
  外部挙動は一切変えず、内部実装を `stripLines(text, predicate)` に共通化した上で以下を追加:
  - `isContextInfoLine()` — `📊 Rate Limit:` 厳密一致のみ（`thread-label-source.ts` の
    `/^[📊📝].+$/` は本文中の正当な `📊`/`📝` 行まで消すため不採用）
  - `isEphemeralProgressLine()` — `/^⏳\s/u`（terminal-mode 心拍表示の行単位判定）
  - `stripAiProgressNoise()` — 🔧/📊 Rate Limit/⏳ をまとめて除去
  - `sanitizeAiAnswer()` — 除去結果が空になる場合（進捗表示しか無い場合）は元テキストの trim に
    フォールバックする（`state==='answered'` で `answer:""` を返すとツール説明と矛盾するため。
    既存慣行 `connection.ts` の `stripProgressMarkers(...).trim() || responseText.trim()` に揃えた）
  - `isMcpAnswerRawMode()` — キルスイッチ判定の純関数
- `apps/server/src/mcp/tools.ts` の 2 箇所に適用:
  - `get_plan`（旧 `latestMessage.content.slice(0, 500)` / `latestMessage.content` 直返し）→
    sanitize を 1 回だけ行い、その結果から `summary` を切るよう変更（先頭バイトのズレ防止）
  - `get_answer` の `answered` 分岐（旧 `latestAiMessage!.content` 直返し）
  - `get_build_status.tail`/`progressTail`、`get_conversation_history`、`search_project_context`、
    WebUI 会話ログ表示、DB の `Message.content` 自体は無変更
- キルスイッチ `DEVRELAY_MCP_ANSWER_RAW=1`（既定 `0` = 整形有効）を追加、`CLAUDE.md` に追記
- 設計判断を `rules/project.md` に 1 節追記（C の抜け穴を別課題として明記）
