# 2026-11-24 06:08 JST ｜ サイクル SB-2.1.1: install-sandbox-host.ps1 が schtasks /Delete で止まる不具合の修正

## 要求

hp630g9 で `install-sandbox-host.ps1 -DeveloperAccount "DESKTOP-Q43QT7L\fwjg2"` を実行すると、
`[OK] Saved deny.json` の直後（429 行）で
`& schtasks /Delete /TN $TaskPath /F 2>$null | Out-Null` が NativeCommandError
（「指定されたファイルが見つかりません」）を出してスクリプトが終了していた。初回インストールで
タスクが存在しないのは正常であり、タスク登録・開発者への実行権付与・最初の IPv4 遮断ルール
作成が一切行われていなかった。

真因: `$ErrorActionPreference = "Stop"` の下では、Windows PowerShell 5.1 が外部コマンドの
標準エラー出力を ErrorRecord にして終了させる。`2>$null` でリダイレクトしても ErrorRecord の
生成自体は防げない。

承認時の人間の判断（3点、いずれも反映）:
1. これまで結果を見ていなかった icacls の `/inheritance:r` と `/grant` は「失敗したら中止」に
   変える（`/remove:g` と削除前の ACL 戻しは「失敗してもよい」のまま）。
2. `sc.exe delete` の後に「サービスが消えるまで最大15秒待つ」ループを追加する。
3. 作業ツリーに残っている前サイクル（スレッド状態バッジ、DB 0037 未適用）の変更とは混ぜず、
   本サイクルのファイルだけをパス指定でコミットする。

devlog のファイル名は `TZ=Asia/Tokyo date '+%Y-%m-%d_%H%M%S'` の形式にする指示あり。

## 実行

対象3本の `.ps1`（`install-sandbox-host.ps1` 24箇所、`uninstall-sandbox-host.ps1` 3箇所、
`apply-sandbox-allowlist.ps1` 0箇所＝外部コマンド呼び出し自体が無い）のうち、同じ地雷
（`$ErrorActionPreference = "Stop"` 下での外部コマンド呼び出し）を踏む箇所を全数洗い出した。

同じリポジトリの `scripts/install-agent.ps1` の `Invoke-LoggedCommand`（975〜1033 行、hp630g9
含む実機で動作確認済みの既存解法）と同じ考え方で、`Invoke-NativeCommand` ヘルパーを
`install-sandbox-host.ps1` / `uninstall-sandbox-host.ps1` の両方に**バイト一致**で新設した:
呼び出し前に `$ErrorActionPreference` を `"Continue"` に退避・呼び出し後に復元、
`$global:LASTEXITCODE = 0` でリセット（コマンド未検出時の残存値対策）、`2>&1` で両ストリームを
手動収集、`-AllowFailure` 指定が無い呼び出しは非ゼロ終了で `exit 1`。既存のコマンド文字列
（`sc.exe create` の引用符の並び等、hp630g9 で動作確認済みのもの）は一字も変えず、
スクリプトブロックで包むだけに留めた（引数配列化はしない）。

削除系（`sc.exe delete`・`schtasks /Delete`・`icacls /remove:g`・削除前の ACL 戻し）は
`-AllowFailure` を付け、429 行の不具合そのものを解消した。これまで結果を見ていなかった
`icacls /inheritance:r` と各 `/grant`（秘密鍵・home・許可リスト4ディレクトリ）は
`-AllowFailure` 無し（人間の判断1）にし、ACL が付かずに進むリスクを塞いだ。`sc.exe delete`
の後に、サービスが消えるまで最大15秒待つループを追加した（人間の判断2、`sc create` の
exit 1073 対策）。

`apply-sandbox-allowlist.ps1` は外部コマンド呼び出しが0件（全て cmdlet）だったため挙動変更は
無し。ヘッダーに「将来 .exe 形式の外部コマンドを足すときは install 側のヘルパーを複製する」旨
の ASCII コメントのみ追記した。

静的ガード `agents/linux/tests/sandbox-scripts-guard.test.mjs` に D1〜D5 を追加した
（`2>` を含むコード行がヘルパー内の1行だけ・外部コマンドの直接呼び出しがヘルパー経由のみ・
ヘルパー自体の必須要素・install/uninstall 間のヘルパー本体バイト一致・削除系と中止系の
`-AllowFailure` の付け分け）。既存ガードの修正は1箇所のみ（A2 の判定を
`$scCreateResult.ExitCode` 経由でも通るように緩和）。

## 検証

  ＋その他、修正1件を含む）
- `node --test --test-concurrency=1 tests/`（agents/linux 全件）: 1765件中 1763 pass / 2 skip
  / 0 fail
- 3ファイルとも非ASCIIバイト0件（`grep -nP '[^\x00-\x7F]'` で確認）、`{`/`}` の個数一致を確認
- install と uninstall の `Invoke-NativeCommand` マーカー間テキストが完全一致することを
  `diff` で確認

- `.ts` ファイルは変更していないため `pnpm build` は不要・サーバー再起動案内も不要

手順3から再開する。
