# 2026-08-29 20:14 JST ｜ core#332: MCP plan の skipPermissions 強制ON解消

## 要求
前サイクルの read-only 調査（#331 直前）で、MCP `submit_instruction` が常に `forceNewSession=true` を送り、
Agent 側がこれを見て plan モードでも `skipPermissions=true`（実質全ツール自動承認）を強制していることが
判明した。`forceNewSession`（resume 抑止）と権限ポリシーが 1 つのフラグに癒着しているのが原因のため、
両者を分離し MCP plan には strictReadonly（allowlist 外は聞かずに deny）を適用する承認済みプランを実装した。
人間承認時の追記で `PLAN_READONLY_TOOLS` に `Read/Glob/Grep/Task/ToolSearch/TaskOutput/TaskStop/WebSearch/WebFetch`
を必ず含めること、判断に迷うツールは deny ではなく allow に倒すことが明示された。

## 実行
`permissionPolicy?: string`（`'interactive'|'strictReadonly'|'skip'`）を新設し、MCP submit は `'strictReadonly'`、
チャット/exec は `'interactive'` を明示送信するよう server 側3箇所（`mcp/tools.ts`/`command-handler.ts`/
`agent-manager.ts`）を新設の純関数 `resolvePermissionPolicy()` に集約。Agent（linux/macos）の `connection.ts` は
`skipPermissions` の導出式から `forceNewSession` を排除し `permissionPolicy` ベースに変更、`onPolicyDenied`
コールバックを新設して plan の deny も `ToolApproval` に記録するようにした。`ai-runner.ts` の plan モード
`canUseTool` は skipPermissions 自動 allow に `!strictReadonly` 条件を追加し、末尾のフォールスルー（従来は
無条件 allow）を allowlist ベースの deny に置き換えた。判定ロジックは linux 側で `plan-permission.ts`
（外部importゼロの純関数）に切り出し、macOS は OS 別自己完結方針に従い同一ロジックを別ファイルに複製した。
exec モードの `canUseTool` は一切触っていない。DB は `ToolApproval.reason` 列を追加し、`prisma migrate dev`
は使わず DDL を `doc/migrations/332_tool_approval_reason.md` に記載（人間が psql で適用）。

## 検証
`pnpm build` を6 workspaceすべてフォアグラウンドで実行し green（packages/shared → agents/linux → agents/macos
→ apps/server → apps/web の順に個別確認後、モノレポ全体でも再確認）。`cd apps/server && pnpm test` は
既存4件 + 新規4件の計8件green、`cd agents/linux && pnpm test` は新規9件green（プラン記載の必須6ケース
すべて含む）。静的確認: `forceNewSession` が `skipPermissions` の導出式に一切現れないこと（linux/macos 両方）、
exec モード `canUseTool` の git diff が 0 行であること、`permissionPolicy` が両 `connection.js`（dist）に
コンパイルされていること、`grep -c 'require(' apps/web/dist/assets/index-*.js` = 0（#310 再発防止）を
それぞれ確認した。このサイクル中は `pm2 restart`/Agent 再起動/プロセス kill/DDL 実行を一切行っていない。

## 発見
plan モードの全 allow は MCP 限定ではなく、チャット plan も従来どおり全 allow のまま残っている
（本サイクルは MCP のみ strictReadonly 化。恒久対応は運用影響が大きいため別サイクル判断とした）。
`DEFAULT_ALLOWED_TOOLS_LINUX` に含まれる `Bash(curl *)` は読み取り目的だが任意の外部 HTTP 送信が可能で、
strictReadonly でも許可されたままになる点は変更せず記録のみとした。旧 Agent は `permissionPolicy` を
無視するため fail-open（サーバー更新直後は MCP plan が従来どおり全 allow）で動作し、全マシンの `u` が
完了するまで機体ごとに挙動がばらつく。実機 E2E（MCP plan から書き込み指示 → deny + `ToolApproval` 記録）
は人間の DB DDL 適用・server 再起動・全マシン `u` 後に別サイクルで実施する。
